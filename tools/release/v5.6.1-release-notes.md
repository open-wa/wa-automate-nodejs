# 🐛 OpenWA 5.6.1 — Fix Node create startup

This patch fixes a second Node startup failure uncovered by running the CommonJS `create(configObject)` reproduction from [#3534](https://github.com/open-wa/wa-automate-nodejs/issues/3534).

OpenWA 5.6.0 removed the EventEmitter2 import failure, but the dynamically imported ESM core still treated its stack-frame file URL as a filesystem path. Chrome could start and then fail before QR login because the packaged runtime assets could not be found. Core now converts that URL with Node's `fileURLToPath()` before resolving the asset directory. The browser assets, including `wapi.js`, are unchanged.

The shared `ev` API continues to emit pairing strings on `qr.<sessionId>`; `qr.**` observes all sessions. The normal terminal renderer uses the native QR event. The patch includes a standalone CommonJS reproduction for the real create path.

```sh
npm install --save-exact @open-wa/wa-automate@5.6.1 @open-wa/driver-puppeteer@5.6.1
```

The fix was checked through real QR startup. Paired messaging readiness and the original Ubuntu/PM2 environment are separate acceptance boundaries.
