# Buttons are back. Meet interactive messages in OpenWA 5.1.

If you gave up on WhatsApp buttons, this release is for you.

OpenWA 5.1 brings them back with an API built around the conversations you want to create: quick replies, service menus, image carousels, booking cards, and forms that return answers your code can use.

**Available to Insiders and above.** Update OpenWA and restart your licensed session to load the new capabilities.

## Give people something to tap

```ts
client.onInteractiveResponse(response => {
  if (response.type === 'reply') {
    console.log(response.id); // 'order' or 'support'
  }
});

await client.sendInteractive(to, {
  type: 'buttons',
  body: 'What can we help you with?',
  actions: [
    { type: 'reply', id: 'order', label: 'Track my order' },
    { type: 'reply', id: 'support', label: 'Talk to support' },
  ],
});
```

Use stable IDs for your application and write button labels for your customers. Lists return the selected row ID; carousel replies identify the option they chose. Subscribe before sending in your application so you can handle an immediate reply.

## Forms, with actual answers

Collect a single choice, several choices, or a sequence of questions inside WhatsApp. `onFormResponse` gives you structured answers keyed by your question IDs, so you can move straight to the next step in your workflow.

```ts
client.onFormResponse(({ answers, originalMessageId }) => {
  console.log(answers);
  // { plan: 'pro', extras: ['delivery', 'gift'] }
  console.log(originalMessageId); // links the response to the sent form
});
```

No scraping the reply text or trying to infer which translated label was selected. Keep the IDs stable and change the wording whenever you need to.

## More ways to build a conversation

- **Buttons:** quick replies, or website, call and copy actions.
- **Lists:** group choices into sections and receive the selected row ID.
- **Forms:** single and multiple selections, with a dedicated response listener.
- **Image carousels:** let people browse cards and choose from them.
- **Booking cards:** present appointment details with a native details view.

All of these use `sendInteractive(to, content)`. The same JSON document works through the SDK and HTTP API. TypeScript autocomplete, validation errors that point to the field, and sensible defaults help you get a message out without learning WhatsApp's internal payload format.

For reusable messages, `defineInteractiveMessage(...)` validates the document and preserves its specific TypeScript type. It's also the format a visual builder can save and export—there's no builder-only format to translate later.

## Built for your integrations

Send through `POST /api/messages/sendInteractive` and subscribe to `interactive.response` on the event stream. SDK users get `onInteractiveResponse` and the focused `onFormResponse` listener, with the sender, chat, response message ID and original message reference.

For developers who already construct protocol payloads, `sendRawMessage` accepts a raw WhatsApp protobuf Message object. Native actions also have an explicit extension format for advanced uses. The guide explains their limits; the typed message variants are the simplest starting point.

## Upgrade and try it

```sh
npm install @open-wa/wa-automate@^5.1.0
```

Or launch the Easy API:

```sh
npx @open-wa/wa-automate@5.1.0 --license-key YOUR_LICENSE_KEY
```

Start with the [interactive messages guide](https://openwa.dev/docs/guides/interactive-messages) for complete examples, media headers, form responses and HTTP calls.

This is the new V5 API; existing V4 button calls aren't the contract for these features. Recipient apps control rendering, and availability can vary with WhatsApp versions. Reply buttons and URL/call/copy actions must be sent separately. Booking cards use WhatsApp's own icon and details layout.
