# Licensed features

Most of open-wa works without a license. A license unlocks the features below for the one WhatsApp number it's assigned to; see [pricing](/docs/licensing/pricing) for what it costs.

## What a license unlocks

A license bought on [openwa.cloud](https://openwa.cloud) unlocks every row in this table.

| Feature | What it lets you do | Methods |
| --- | --- | --- |
| Messaging new numbers | Start a chat with a number the account hasn't talked to before | `sendText` and other sends to a new chat |
| Stories and status | Post, read and delete status updates | `postTextStatus`, `postImageStatus`, `postVideoStatus`, `getStories`, `getStatus`, `deleteStatus`, `deleteAllStatus` |
| Insiders methods | Look up numbers and profiles, read starred messages and orders, change the profile picture | `checkNumberStatus`, `getNumberProfile`, `getStarredMessages`, `getOrder`, `setProfilePicture` |
| Interactive messages | Send buttons, lists, forms, carousels and booking cards | `sendInteractive`, `sendRawMessage`, and the older `sendButtons`, `sendAdvancedButtons` and `sendListMessage` |

`createGroup` and `joinGroupViaLink` are marked `restricted` in the API reference; a license covers them too. Every other method is free to use, and sending to an existing chat never needs a license. The API reference marks each gated method with a license badge.

### Keys bought on Gumroad

Keys bought on Gumroad keep working and unlock what their tier included:

| Gumroad tier | Unlocks |
| --- | --- |
| Restricted or Premium license key | Everything above |
| Insiders Program | Insiders methods and interactive messages |
| Text, image or video story key (including Early Bird image story) | Stories and status, Insiders methods and interactive messages |

## Apply a key

In the SDK, pass the key to `create()`:

```ts
import { create } from '@open-wa/wa-automate';

const client = await create({
  sessionId: 'sales',
  licenseKey: process.env.WA_LICENSE_KEY,
});
```

For the Easy API, use the `--license-key` flag, the `WA_LICENSE_KEY` environment variable or `licenseKey` in `wa.config.js`:

```bash
WA_LICENSE_KEY='YOUR-LICENSE-KEY' npx @open-wa/wa-automate --session-id sales
```

You can also apply a key to a running Easy API session from the dashboard's license badge; see [refresh a session](/docs/sessions/refresh). Treat the key as a secret and keep it out of source control.

## Check that it worked

Read the `license` object from `/health`:

```bash
curl http://127.0.0.1:8080/health
```

A session started without a key reports:

```json
{
  "license": {
    "status": "missing",
    "source": "none",
    "keyType": "none",
    "detail": "No license is applied."
  }
}
```

With a working key, `status` is `valid`. In the SDK, `await client.getLicenseFeatures()` returns the same `status`.

| Status | Meaning |
| --- | --- |
| `valid` | The key was accepted for this number and the licensed features are on. |
| `missing` | No key reached the session. Unlicensed methods work as normal. |
| `invalid` | The key was rejected, usually because it's assigned to another number or the subscription ended. |
| `expired` | The license period ended. |
| `metadata_only` | The key couldn't be confirmed, so licensed features stay off until it can. |

A key problem never stops the session: it still becomes ready, and only the licensed features stay off. If a licensed method fails while the status is `valid`, check that you're calling it on the session the key was applied to. When asking for help, include the `license` object with the key and number masked.
