# Session events

When you need lifecycle visibility outside the client convenience methods, use the shared event emitter `ev`.

<Callout type="info" title="Think of ev as the runtime event bus">
  Use it when you need authentication lifecycle, QR capture, session data, or
  wildcard namespace visibility outside the higher-level convenience listeners.
</Callout>

```ts
import { ev } from '@open-wa/wa-automate';
```

<Steps>
  <Step title="Subscribe to QR generation when you need operator-facing auth">

## Capture QR codes

```ts
import { ev } from '@open-wa/wa-automate';
import fs from 'node:fs';

ev.on('qr.**', async (qrcode) => {
  const imageBuffer = Buffer.from(
    qrcode.replace('data:image/png;base64,', ''),
    'base64',
  );

fs.writeFileSync('qr_code.png', imageBuffer);
});
```

  </Step>
  <Step title="Capture session data if you manage your own restore flow">

## Capture session data

```ts
ev.on('sessionData.**', async (sessionData, sessionId) => {
  // store or encrypt the latest auth payload for your own workflow
});
```

  </Step>
  <Step title="Use wildcard namespaces carefully in multi-session environments">

## Listen to launch namespaces

Event names are typically shaped like:

```text
namespace.sessionId
```

Examples:

```ts
ev.on('qr.**', () => {});
ev.on('sessionData.**', () => {});
ev.on('**.session1', () => {});
ev.on('**.**', (data, sessionId, namespace) => {
  console.log(namespace, sessionId, data);
});
```

Use wildcard subscriptions carefully in multi-session environments so you do not lose track of which session produced the event.

  </Step>
</Steps>
