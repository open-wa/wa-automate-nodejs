# Keep secrets out of config

Keep secrets out of files you commit. Load them into `process.env`, then pass each value to the setting that uses it. open-wa's own settings read `WA_*` variables; every other name is yours to map in a config file.

## Load a `.env` file

The Easy API reads `WA_*` variables from the environment, but it doesn't load a `.env` file for you. Node 22 can, with `process.loadEnvFile`, which is what projects made with `npm init @open-wa` do. Install the Easy API and the webhook plugin used below:

```bash
npm install @open-wa/wa-automate @open-wa/integration-webhook
```

Create `.env` next to the config file and add it to `.gitignore`:

```dotenv
WA_API_KEY=replace-with-a-long-random-key
WA_SESSION_ID=sales
WEBHOOK_SECRET=replace-with-webhook-secret
CHATWOOT_URL=https://chatwoot.example/app/accounts/1/inboxes/2
CHATWOOT_API_ACCESS_TOKEN=replace-with-chatwoot-token
OPENWA_PUBLIC_URL=https://openwa-api.example
```

Load it at the top of `wa.config.mjs` and fail fast when a secret is missing:

```js title="wa.config.mjs"
import { existsSync } from 'node:fs';

if (existsSync('.env')) process.loadEnvFile('.env');

const required = (name) => {
  const value = process.env[name];
  if (!value) throw new Error(`${name} is required`);
  return value;
};

export default {
  apiKey: required('WA_API_KEY'),
  sessionId: process.env.WA_SESSION_ID ?? 'sales',
  plugins: ['@open-wa/integration-webhook'],
  pluginConfig: {
    webhook: {
      url: 'https://your-app.example/webhooks/open-wa',
      events: ['message.received'],
      headers: { 'X-Webhook-Secret': required('WEBHOOK_SECRET') },
    },
  },
};
```

```bash
npx wa-automate --config ./wa.config.mjs
```

`WA_API_KEY` and `WA_SESSION_ID` are open-wa settings, so the Easy API would also pick them up from the environment on its own. `WEBHOOK_SECRET` and the Chatwoot names are your own, so the config file maps them onto the plugin settings that use them.

In the SDK, `create()` doesn't read the environment at all. Pass values explicitly, for example `create({ licenseKey: process.env.WA_LICENSE_KEY })`.

## Docker

Pass secrets to a container as environment variables; the [Docker guide](/docs/getting-started/docker) has complete commands. Compose reads `.env` only to fill in the compose file, so list every variable the container needs under `environment`.

The container doesn't read Docker secret files on its own. If your platform mounts a secret under `/run/secrets`, use an entrypoint that reads the file, exports it as `WA_API_KEY`, and then starts open-wa. Restrict access to the secret file and the session profile.

## Plugin settings

`plugins` lists npm packages or local paths, and `pluginConfig` holds each plugin's settings under its name. The plugin validates and reads its own section.

### Webhook

The [webhook plugin](/docs/guides/receive-webhooks) takes `url`, optional `events` and optional `headers` under `pluginConfig.webhook`. The top-level `webhook` setting and the `--webhook` flag don't deliver events; use the plugin.

### Chatwoot

```bash
npm install @open-wa/integration-chatwoot
```

```js
export default {
  plugins: ['@open-wa/integration-chatwoot'],
  pluginConfig: {
    chatwoot: {
      chatwootUrl: process.env.CHATWOOT_URL,
      chatwootApiAccessToken: process.env.CHATWOOT_API_ACCESS_TOKEN,
      apiHost: process.env.OPENWA_PUBLIC_URL,
      apiKey: process.env.WA_API_KEY,
      forceUpdateCwWebhook: true,
    },
  },
};
```

`chatwootUrl` is the Chatwoot account URL, optionally with the inbox path, `chatwootApiAccessToken` authenticates calls to Chatwoot, and `apiHost` is the public address Chatwoot can reach open-wa on. The [Chatwoot guide](/docs/guides/chatwoot) covers the rest.

### Your own plugin

A plugin's settings mean whatever that plugin defines, so validate them in the plugin's `configSchema`:

```js
export default {
  plugins: ['./plugins/my-plugin.mjs'],
  pluginConfig: {
    'my-plugin': { apiKey: process.env.MY_PLUGIN_API_KEY },
  },
};
```

## Rules to follow

- Keep API keys, license keys, webhook secrets and integration tokens in environment variables or a secret manager.
- Add `.env` and secret directories to `.gitignore`, and never commit session files (`*.data.json`).
- Don't log whole config objects; log `hasKey: Boolean(config.apiKey)` instead of the key.
- To rotate a secret, change the value and restart open-wa so it's read again.
- Treat the session file (`<sessionId>.data.json`) as a secret, because it holds the WhatsApp login.
