# Messages and message events

This guide covers the everyday message work: reading what arrives, replying, formatting, attachments, albums and delivery tracking. The examples assume a `client` from `create()`. Chat IDs such as `447700000000@c.us`, group IDs and LIDs are explained in the [chat ID primer](/docs/guides/chatid-primer).

## Receive messages

```ts
client.onMessage((message) => {
  console.log(message.from, message.body);
});

client.onAnyMessage((message) => {
  console.log(message.fromMe ? 'sent' : 'received', message.body);
});
```

`onMessage` fires for incoming messages only, while `onAnyMessage` also fires for messages this account sends, so use it when you want both directions in one place. Each listener returns a handle; call `handle.off()` to remove it. To receive messages over HTTP or in another language, see [receive messages](/docs/guides/receive-messages).

## Message object

Messages are plain objects. WhatsApp can add fields, so treat the shape as extensible and read only what you need.

| Field | Description |
| --- | --- |
| `id` | The message ID. Pass it to `reply`, `forwardMessages` or lookup methods. |
| `body` | Text of a text message. Media messages can have an empty body. |
| `type` | Message type, such as `chat`, `image`, `video`, `album`, `document`, `ptt`, `location`, `buttons_response` or `list_response`. |
| `event` | Event details on an `event_creation` message. See [calendar events and RSVPs](/docs/guides/whatsapp-events). |
| `from` | The chat that sent the message: the contact in a direct chat, the group in a group. |
| `to` | The chat or account that received the message. |
| `chatId` | The conversation's chat ID. |
| `sender` | Contact details for the sender. |
| `senderId` | Sender contact ID when available, which is useful in groups. |
| `author` | The group participant who sent the message. |
| `fromMe` | `true` when this account sent the message. |
| `timestamp` / `t` | Unix timestamps from WhatsApp. |
| `isGroupMsg` | `true` for a group message. |
| `isMedia` / `isMMS` | Media flags; check them before downloading. |
| `caption` | Caption of an image, video or document. |
| `expectedImageCount` / `expectedVideoCount` | Item counts declared by an album. They don't confirm that every item has arrived. |
| `parentMsgKey` / `associationType` | The parent message and association type of an album item (`MEDIA_ALBUM`). |
| `isGif` | Whether a video plays as a GIF. |
| `mentionedJidList` | Contact IDs mentioned in the message. |
| `ack` | Delivery state of an outgoing message; see [acknowledgements](#acknowledgements). |
| `quotedMsg` / `quotedMsgObj` | The quoted message, when available. |

## Send text and replies

```ts
await client.sendText(chatId, 'Hello');
await client.reply(chatId, 'Thanks, got it.', messageId);
```

`sendText(chatId, text)` returns the message ID or throws a `SendTextError`. `reply` quotes the message whose ID you pass. A returned ID confirms the send, not delivery or reading, and starting a chat with a new number needs a [license](/docs/licensing/pricing).

```ts
import { SendTextError } from '@open-wa/wa-automate';

try {
  await client.sendText(chatId, 'Hello');
} catch (error) {
  if (!(error instanceof SendTextError)) throw error;
  console.error(error.code, error.message);
  if (error.outcome === 'unknown') console.error('Check the chat before sending again.');
}
```

`INVALID_ARGUMENT`, `LICENSE_REQUIRED` and `SEND_REJECTED` have `outcome: 'not_sent'`, so nothing reached the chat. `SEND_FAILED` and `INVALID_SEND_RESULT` have `outcome: 'unknown'`, which means the message may already be there; their `cause` holds the underlying failure. open-wa never retries `sendText` for you.

## Formatting

WhatsApp formats text with inline markers, so put them in the message body:

```ts
await client.sendText(chatId, 'Order *confirmed* for _today_.');
await client.sendText(chatId, '~cancelled~ ```monospace```');
```

## Mentions

Mentions are Easy API methods. Put the `@number` text in the content and pass the mentioned contact IDs:

```bash
curl --fail-with-body http://localhost:8080/api/messages/sendTextWithMentions \
  -H "Content-Type: application/json" -H "X-API-Key: $WA_API_KEY" \
  -d '{"to":"120363000000000000@g.us","content":"Hello @447700000000, can you check this?","mentions":["447700000000@c.us"]}'
```

Set `"hideTags": true` to notify the mentioned people without showing the tags. `sendReplyWithMentions` takes the same fields plus `replyMessageId` to quote a message.

## Attachments

Text needs only a chat ID and a string. Attachments take a file, a filename and an options object for the caption:

```ts
await client.sendImage(chatId, './receipt.png', 'receipt.png', { caption: 'Receipt attached' });
```

Media methods accept a local path, URL, data URL, base64 string or `Buffer`. `sendFile` and `sendImage` detect whether to show an image, video, audio clip or document; `sendAudio`, `sendPtt` and `sendVideoAsGif` cover the other cases. [Media](/docs/guides/media) explains captions, view-once media, video notes and document presentation.

## Albums

An incoming album is a container message with `type: 'album'`, declared image and video counts, and an empty body. Its images and videos arrive as separate messages with `associationType: 'MEDIA_ALBUM'` and a `parentMsgKey` that matches the container's ID, and captions belong to those items.

```ts
client.onMessage(async (message) => {
  if (message.type === 'album') {
    const loaded = await client.getAlbumMessages(message.id);
    if (loaded !== false) console.log('Loaded items so far:', loaded.length);
  }
  if (message.associationType === 'MEDIA_ALBUM' && message.parentMsgKey) {
    const dataUrl = await client.decryptMedia(message);
    console.log('Album item', message.parentMsgKey, dataUrl.length);
  }
});
```

`getAlbumMessages(albumId)` returns the items loaded so far, or `false` when the ID isn't a loaded album. The container can arrive before its items, so handle each item as it arrives rather than waiting for the full count.

To send an album, pass two or more images or videos as data URLs:

```ts
import { readFile } from 'node:fs/promises';

const encode = async (path: string, mime: string) =>
  `data:${mime};base64,${(await readFile(path)).toString('base64')}`;

const result = await client.sendAlbum(chatId, [
  { file: await encode('./photo.jpg', 'image/jpeg'), filename: 'photo.jpg' },
  { file: await encode('./clip.mp4', 'video/mp4'), filename: 'clip.mp4' },
  { file: await encode('./loop.mp4', 'video/mp4'), filename: 'loop.mp4', isGif: true },
], 'One caption for the album');

console.log(result.albumId, result.messageIds);
```

The caption goes on the first item, and an optional fourth argument quotes a loaded message. For a GIF, supply an MP4 with `isGif: true`, because the method doesn't convert GIF files. Documents and audio are rejected, and the destination chat must already be loaded. The result lists the album ID and item IDs in input order. If the send fails partway, the error includes the IDs submitted so far; check the chat before retrying, since the album may be partly sent.

## Polls and interactive messages

For buttons, lists, forms, carousels and bookings, use [`sendInteractive`](/docs/guides/interactive-messages), which needs a [license](/docs/licensing/pricing). `sendButtons`, `sendAdvancedButtons` and `sendListMessage` are older methods kept for existing integrations.

Polls need no license:

```ts
await client.sendPoll(chatId, 'Which day works best?', ['Monday', 'Tuesday', 'Wednesday'], {
  selectableCount: 1,
});
```

Votes arrive through `onPollVote`, and `getPollResults` returns the totals. [Polls and pinned messages](/docs/guides/polls-and-pins) covers closing times, voting and pinning.

## Forward messages

```ts
await client.forwardMessages('447700900123@c.us', [messageId], true);
```

The third argument skips messages this account sent.

## Acknowledgements

Subscribe before sending to watch a message move from sent to read:

```ts
const subscription = client.onAck((message) => {
  console.log(message.id, message.ack);
});
```

The callback receives the message with its current `ack` value. Some fields can be missing while WhatsApp is still loading the message.

| `message.ack` | Meaning |
| --- | --- |
| `-1` | Error |
| `0` | Pending |
| `1` | Accepted by the server |
| `2` | Delivered to the recipient's device |
| `3` | Read |
| `4` | Played |

Call `subscription.off()` to stop listening.

## Location messages

```ts
await client.sendLocation(chatId, 51.5072, -0.1276, 'London');
```

An incoming location message carries `lat`, `lng` and `loc`.

## When a send fails

| Problem | What to check |
| --- | --- |
| Invalid chat ID | The value matches a contact, group or LID format. See the [chat ID primer](/docs/guides/chatid-primer). |
| Session not ready | Authentication finished and the session is ready before you send. |
| Media rejected | The MIME type, data URL, filename and file size. |
| Message not delivered | `onAck` updates; retry from one place only, after reviewing the failure. |
| Account restricted | Slow or pause the queue and keep the error. |

Send at a controlled rate, avoid bulk or repeated content and short retry loops, and read [rate limits](/docs/operations/rate-limits) before running automation in production.
