# MCP server

The Easy API has a built-in Model Context Protocol (MCP) endpoint. Turn it on
and an AI assistant can call every Easy API method as a tool: read chats, send
messages and media, look up contacts and manage groups.

<Callout type="warning" title="The agent gets full access to the account">
There are no per-tool permissions. Any client with the API key can read every
chat and send to anyone. Use a dedicated WhatsApp account for agent work, keep
the endpoint off the public internet, and watch what the agent does while you
test prompts.
</Callout>

## Turn it on

MCP is configured in `wa.config.*`; there's no `--mcp` flag. The Easy API
refuses to start with MCP enabled and no `apiKey`.

```js title="wa.config.mjs"
export default {
  apiKey: process.env.WA_API_KEY,
  mcp: {
    enabled: true,
    path: '/mcp',
    exposeToolsMeta: true,
  },
};
```

```bash
WA_API_KEY="your-secure-key" npx @open-wa/wa-automate --config ./wa.config.mjs --session-id mcp
```

The endpoint is `http://localhost:8080/mcp` (on your machine). It uses the
Streamable HTTP transport on that single path, and tool calls wait until the
WhatsApp session is ready.

Check it from `/health`:

```bash
curl -s http://localhost:8080/health | jq '.capabilities | {mcpEnabled, mcpAvailable, mcpPath}'
```

`mcpEnabled: false` means the config wasn't loaded or `mcp.enabled` isn't set.
`mcpAvailable: false` means there's no API key. With `exposeToolsMeta`, you can
also list the generated tools:

```bash
curl -s http://localhost:8080/meta/mcp-tools.json | jq '.endpoint, .requiresApiKey, (.tools | length)'
```

That file shows what's exposed but isn't an MCP handshake. To test the
connection properly, connect a real MCP client and call `tools/list`.

## Connect an AI client

Every request must carry the Easy API key in `X-API-Key` (`api_key` and `key`
headers also work).

<Tabs items={['Claude Desktop', 'Cursor', 'Windsurf', 'Custom client']}>
<Tab value="Claude Desktop">

Add to `claude_desktop_config.json`, then restart Claude Desktop:

```json
{
  "mcpServers": {
    "open-wa": {
      "url": "http://localhost:8080/mcp",
      "headers": {
        "X-API-Key": "your-secure-key"
      }
    }
  }
}
```

If the tools don't appear, check the header value and that the Easy API loaded
your config.

</Tab>
<Tab value="Cursor">

In Cursor's settings, add an MCP server with URL `http://localhost:8080/mcp`
and header `X-API-Key: your-secure-key`, then test the connection.

</Tab>
<Tab value="Windsurf">

In Windsurf's settings, add an MCP server with URL `http://localhost:8080/mcp`
and an `X-API-Key` header set to your API key, then verify the connection.

</Tab>
<Tab value="Custom client">

Connect to `http://localhost:8080/mcp` with the Streamable HTTP transport, send
`X-API-Key` on every request, call `tools/list` after the handshake and
`tools/call` to run a tool.

</Tab>
</Tabs>

## What the agent can do

Each Easy API method becomes a tool with the method's name, its description and
typed parameters, so the tool list matches the
[HTTP API](/docs/reference/client/client). That includes reading all messages,
sending to any contact or group, sending media, reading contacts and creating,
changing or leaving groups.

If the API key leaks or the endpoint is reachable from the internet, whoever
has it controls the account. Keep the key secret, put the endpoint behind HTTPS
and a reverse proxy for remote use, and review activity in:

- the Neo dashboard's MCP page at `/dashboard/mcp`, which also has ready-made client snippets;
- your Easy API and reverse proxy access logs;
- the session's event log.

## Configuration

| Field | Default | Meaning |
| --- | --- | --- |
| `mcp.enabled` | `false` | Serve the MCP endpoint. Needs `apiKey`. |
| `mcp.path` | `"/mcp"` | URL path of the endpoint. |
| `mcp.exposeToolsMeta` | `true` | Serve `/meta/mcp-tools.json` for the dashboard and debugging. |
| `mcp.events` | enabled | Event subscriptions for ChatGPT; see [Watch WhatsApp from ChatGPT](/docs/guides/mcp-events). |

To set it from the environment, pass the whole object as JSON in `WA_MCP`;
there are no separate `WA_MCP_ENABLED` or `WA_MCP_PATH` variables:

```bash
WA_MCP='{"enabled":true,"path":"/mcp","exposeToolsMeta":true}'
```

## Without MCP

An agent can also use the plain HTTP API:

- interactive docs at `http://localhost:8080/api-docs/` (on your machine);
- the OpenAPI schema at `/meta/swagger.json`;
- a Postman collection at `/meta/postman.json`.

This docs site publishes `/llms.txt`, `/llms-full.txt` and per-page Markdown at
`/llms.mdx/docs/…` for agents that read documentation, plus
`/.well-known/agent-skills.index.json` and `/.well-known/api-catalog`. These
describe open-wa; to act on WhatsApp, the agent still connects to your Easy API.
