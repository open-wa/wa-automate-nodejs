# Model Context Protocol (MCP) integration

Use the **Model Context Protocol (MCP)** integration to expose open-wa Easy API methods as structured tools for AI assistants (such as Claude Desktop, Cursor, or custom agents).

<Callout type="info">
**Easy API integration only:** MCP is provided exclusively through the Easy API daemon layer. It is not available as a direct function call inside embedded `createClient()` custom code applications.
</Callout>

<Callout type="warning">
**Version 5 alpha requirement:** The runtime mounts the MCP adapter when `mcp.enabled` is `true` in `wa.config.mjs`. Server initialization fails if no `apiKey` is configured. The CLI does not parse a standalone `--mcp` flag; enable MCP in your configuration file.
</Callout>

<Callout type="warning">
When enabled, an authenticated MCP client can read conversation history and dispatch messages through your WhatsApp session. Always protect the endpoint with an API key and avoid public internet exposure without an authenticating reverse proxy.
</Callout>

## Security checklist before you enable MCP

- Configure an `apiKey` in `wa.config.mjs`.
- Provide the API key in the `X-API-Key` request header from your MCP client.
- Run the server behind HTTPS or an authenticated reverse proxy before connecting remote agents.
- Use a dedicated WhatsApp account for agent testing and development.
- Monitor tool execution logs in your terminal and the web dashboard.

## Capabilities provided by MCP

When enabled, the MCP adapter maps Easy API methods to typed tools:

- Reading incoming messages and chat history
- Sending text, media, documents, and contact cards
- Managing group membership and group settings
- Querying contact profiles and presence state

## Compare MCP with the direct HTTP API

| Feature | Model Context Protocol | Direct HTTP API |
| --- | --- | --- |
| Tool discovery | Automatic schema discovery via `tools/list` | Manual inspection of OpenAPI specifications |
| Tool invocation | Standardized JSON-RPC tool calls | Custom HTTP `POST` requests |
| Session readiness | Automatically blocks tool execution until session connects | Requires manual polling of health endpoints |
| Endpoint structure | Single Streamable HTTP endpoint (`/mcp`) | Multiple distinct REST endpoints |

## Quickstart

Configure MCP in `wa.config.mjs`:

```js
export default {
  apiKey: process.env.WA_API_KEY,
  port: 8080,
  mcp: {
    enabled: true,
    path: '/mcp',
    exposeToolsMeta: true,
  },
};
```

Start the Easy API server:

```bash
WA_API_KEY="YOUR_SECURE_KEY" npx @open-wa/wa-automate@alpha --config ./wa.config.mjs
```

The MCP endpoint is mounted at:

```text
http://localhost:8080/mcp
```

### Verify enabled capabilities

Check the `/health` endpoint to confirm MCP availability:

```bash
curl -s http://localhost:8080/health | jq '.capabilities.mcpEnabled, .capabilities.mcpAvailable, .capabilities.mcpPath'
```

Expected JSON response:

```json
true
true
"/mcp"
```

When `exposeToolsMeta` is enabled, view the generated tool catalog at `/meta/mcp-tools.json`:

```bash
curl -s http://localhost:8080/meta/mcp-tools.json | jq '.endpoint, .requiresApiKey, (.tools | length)'
```

## Agent discovery endpoints

The runtime exposes standard agent discovery metadata:

- `http://localhost:8080/.well-known/agent-tools`: JSON metadata describing available tools and authentication requirements
- `http://localhost:8080/meta/mcp-tools.json`: Full JSON array of tool definitions, descriptions, and parameter schemas

## Streamable HTTP transport

The adapter implements the **Streamable HTTP** transport for MCP:

- **Single endpoint**: All JSON-RPC messages and tool calls route through `/mcp`.
- **Readiness gating**: Tool executions block until the underlying WhatsApp session completes authentication.
- **Stateful sessions**: Maintains connection state across sequential requests.

## Configure AI clients

Add the following configurations to connect your AI assistant:

<Tabs items={['Claude Desktop', 'Cursor', 'Windsurf', 'Custom client']}>
<Tab value="Claude Desktop">

Add to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "open-wa": {
      "url": "http://localhost:8080/mcp",
      "headers": {
        "X-API-Key": "YOUR_SECURE_KEY"
      }
    }
  }
}
```

Restart Claude Desktop to load the tools into your assistant context.

</Tab>
<Tab value="Cursor">

1. Open **Cursor Settings** > **Features** > **MCP**.
2. Click **Add New MCP Server**.
3. Set the Type to **SSE** or **HTTP**.
4. Set the URL to `http://localhost:8080/mcp`.
5. Add the header `X-API-Key: YOUR_SECURE_KEY`.
6. Click **Test Connection**.

</Tab>
<Tab value="Windsurf">

1. Open **Windsurf Settings** > **MCP Plugins**.
2. Add a new server configuration with URL `http://localhost:8080/mcp`.
3. Include the `X-API-Key: YOUR_SECURE_KEY` header.
4. Verify the connection status.

</Tab>
<Tab value="Custom client">

When connecting programmatically with the Model Context Protocol SDK:

1. Initialize a Streamable HTTP transport targeting `http://localhost:8080/mcp`.
2. Attach `X-API-Key: YOUR_SECURE_KEY` to outgoing headers.
3. Call `tools/list` to inspect available tool signatures.
4. Invoke methods using `tools/call`.

</Tab>

## Security model

### API key enforcement

Every MCP request must provide a valid API key via `X-API-Key`, `api_key`, or `key` request headers. The server rejects unauthenticated requests immediately.

### Accessible data

The adapter exposes all registered Easy API methods as tools. An authenticated agent can:

- Read messages and conversation threads
- Dispatch messages to contacts and groups
- Modify group settings and participants
- Download and decrypt media attachments

### Permission scopes

The current version 5 alpha does not enforce fine-grained tool scopes. Any authenticated agent has access to all exposed methods. Ensure you only connect trusted AI clients.

### Audit agent actions

Monitor AI agent actions through:

- The web dashboard MCP panel at `http://localhost:8080/dashboard/mcp`
- Easy API HTTP access logs
- Browser session event logs

## Tool discovery

### Dynamic tool generation

The MCP adapter inspects the internal OpenAPI schema registry and automatically generates tool schemas with parameter types and descriptions.

### List available tools

Connect using an MCP client and dispatch a `tools/list` request to view all supported methods.

### Parity with the HTTP API

All methods documented in the interactive OpenAPI specification (`http://localhost:8080/api-docs/`) are available as MCP tools.

## Web dashboard MCP panel

When enabled, navigate to `http://localhost:8080/dashboard/mcp` in your browser to view:

- **Connection status**: Current MCP adapter health and readiness
- **Client snippets**: Generated configuration snippets for Claude Desktop, Cursor, and Windsurf
- **Tool catalog**: Interactive browser for all generated tool definitions and parameters

## Configuration reference

In `wa.config.mjs`:

```js
export default {
  apiKey: "YOUR_SECURE_KEY",
  mcp: {
    enabled: true,
    path: "/mcp",
    exposeToolsMeta: true,
  },
};
```

### Properties

- `mcp.enabled`: Enable or disable the MCP adapter (default: `false`)
- `mcp.path`: URL path for the Streamable HTTP endpoint (default: `"/mcp"`)
- `mcp.exposeToolsMeta`: Expose tool schema JSON at `/meta/mcp-tools.json` (default: `true`)

## Direct HTTP alternative

If you prefer not to use MCP, interact with the HTTP API directly:

- **Interactive OpenAPI documentation**: `http://localhost:8080/api-docs/`
- **OpenAPI JSON schema**: `http://localhost:8080/meta/swagger.json`
- **Postman collection**: `http://localhost:8080/meta/postman.json`

## Machine-readable documentation

AI agents can parse documentation directly using specialized endpoints:

- `/llms.txt`: Summary index of documentation pages
- `/llms-full.txt`: Full aggregated documentation content
- `/llms.mdx/docs/$`: Clean markdown source for individual pages
