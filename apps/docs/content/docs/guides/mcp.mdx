# MCP server

Connect a local tool or AI client to WhatsApp through the Easy API's Model
Context Protocol (MCP) endpoint. This walkthrough reads the WhatsApp Web
version without opening a chat or sending a message. You need Node.js 22.21.1 or
newer, npm, curl, and a dedicated WhatsApp test account you can link from your
phone.

<Callout type="warning" title="The Easy API key grants write access too">
The same key authenticates both Easy API and MCP requests. A client with the
key can call the tools available to the linked session, including reading
chats, sending messages and changing groups, subject to the session's feature
and license limits. open-wa offers no per-tool permissions or read-only key.
A read-only tool annotation is a hint for the client. Keep the server on
loopback, keep the key private and link only your test account for this guide.
</Callout>

## Start the MCP server locally

In a new directory, create `wa.config.mjs`. MCP is enabled through config.

```js title="wa.config.mjs"
const apiKey = process.env.WA_API_KEY;
if (!apiKey) throw new Error('Set WA_API_KEY before starting open-wa');

export default {
  host: '127.0.0.1',
  port: 8080,
  apiKey,
  mcp: {
    enabled: true,
    path: '/mcp',
    exposeToolsMeta: true,
    events: { enabled: false },
  },
};
```

Generate a key for this local session with
`node -p "require('node:crypto').randomBytes(32).toString('hex')"`.
In both terminals, set `WA_API_KEY` to the generated value. Start open-wa in
one terminal from the directory with `wa.config.mjs`.

```bash
export WA_API_KEY='replace-with-your-generated-key'
npx @open-wa/wa-automate@5.10.0 --config ./wa.config.mjs --session-id mcp-test
```

On the test phone, open **WhatsApp → Linked devices → Link a device** and scan
the QR code. Keep open-wa running. Check `/health` from another terminal.
Wait for `connected`, `session.ready` and `capabilities.mcpAvailable` to be `true`.

```bash
curl --fail-with-body http://127.0.0.1:8080/health
```

## Call one read-only tool

Use a local client that supports [MCP `2026-07-28` over Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http).

1. Add `http://127.0.0.1:8080/mcp` as a Streamable HTTP server and configure the client to send `X-API-Key` with the value of `WA_API_KEY` on every request.
2. List the server's tools with `tools/list` and select `session.getWAVersion`.
3. Call the tool with empty arguments. In a client that accepts raw tool parameters, use:

   ```json
   {
     "name": "session.getWAVersion",
     "arguments": {}
   }
   ```

The tool returns the WhatsApp Web version as text in `result.content[0].text`.
The version varies by session. A missing or incorrect API key returns HTTP
`401`. The Neo dashboard at `/dashboard/mcp` and `/meta/mcp-tools.json` also
show the available tools.

## Configuration

| Field | Default | Meaning |
| --- | --- | --- |
| `mcp.enabled` | `false` | Serve the MCP endpoint. Needs `apiKey`. |
| `mcp.path` | `"/mcp"` | URL path of the endpoint. |
| `mcp.exposeToolsMeta` | `true` | Serve `/meta/mcp-tools.json` for the dashboard and debugging. |
| `mcp.events` | enabled | Event subscriptions by poll, stream or webhook; see [Watch WhatsApp from ChatGPT](/docs/guides/mcp-events). |

To set it from the environment, pass the whole object as JSON in `WA_MCP`;
there are no separate `WA_MCP_ENABLED` or `WA_MCP_PATH` variables:

```bash
WA_MCP='{"enabled":true,"path":"/mcp","exposeToolsMeta":true}'
```

## Without MCP

An agent can also use the plain HTTP API:

- interactive docs at `http://localhost:8080/api-docs/` (on your machine);
- the OpenAPI schema at `/meta/swagger.json`;
- a Postman collection at `/meta/postman.json`.

This docs site publishes `/llms.txt`, `/llms-full.txt` and per-page Markdown at
`/llms.mdx/docs/…` for agents that read documentation, plus
`/.well-known/agent-skills.index.json` and `/.well-known/api-catalog`. These
describe open-wa; to act on WhatsApp, the agent still connects to your Easy API.
