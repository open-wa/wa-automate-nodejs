# S3 media storage

WhatsApp media links expire. `@open-wa/integration-s3` decrypts incoming media
and uploads it to your object storage (AWS S3, Google Cloud Storage,
DigitalOcean Spaces, Wasabi or Backblaze), then gives you a `cloudUrl` you can
store with the message.

## Upload media from your message handler

Install the SDK and the integration:

```bash
npm install @open-wa/wa-automate @open-wa/integration-s3
```

Create an `S3Uploader` and call it from `onMessage`. The upload is awaited, so
you have the URL before you hand the message on:

```js title="app.mjs"
import { create } from '@open-wa/wa-automate';
import { S3Uploader } from '@open-wa/integration-s3';

const uploader = new S3Uploader({
  provider: 'aws',
  bucket: process.env.MEDIA_BUCKET,
  region: process.env.MEDIA_REGION || 'eu-west-2',
  accessKeyId: process.env.MEDIA_ACCESS_KEY_ID,
  secretAccessKey: process.env.MEDIA_SECRET_ACCESS_KEY,
  public: false,
  directory: 'DATE_CHAT',
  ignoreHostAccount: true,
}, {
  error: (message) => console.error('S3 upload failed', message),
});

const client = await create({ sessionId: 'sales' });

function base64Payload(dataUrl) {
  const match = /^data:[^,]+;base64,([A-Za-z0-9+/]+={0,2})$/.exec(String(dataUrl));
  if (!match) throw new Error('decryptMedia did not return a base64 data URL');
  return match[1];
}

client.onMessage(async (message) => {
  if (!message.deprecatedMms3Url || !message.mimetype) return;

  const cloudUrl = await uploader.uploadMedia(message, {
    decryptMedia: async (media) => base64Payload(await client.decryptMedia(media)),
  });

  if (cloudUrl) console.info('media stored', { messageId: message.id, cloudUrl });
});

process.once('SIGTERM', async () => {
  await uploader.waitForQueue();
  await uploader.close();
  await client.stop('SIGTERM');
});
```

The `MEDIA_*` names are this example's own variables. `provider`,
`accessKeyId`, `secretAccessKey` and `bucket` are required; `region` is
optional. `provider` is one of `aws`, `gcp`, `do`, `wasabi` or `backblaze`.
There is no `endpoint` option, so a generic S3-compatible endpoint
configuration won't carry over.

`uploadMedia()` returns the URL, or `null` when decryption or upload fails. It
logs the failure through the `error` callback and doesn't retry, so record
failed copies yourself if you need every file archived.

<Callout type="info" title="Register it as a plugin instead">
`s3Plugin(config)` adds `cloudUrl` to each received message in the background,
without awaiting. It's a plugin object rather than a package name, so it needs
the lower-level `createClient`; see
[createClient and drivers](/docs/concepts/create-client-and-drivers). Your
listeners can't rely on `cloudUrl` being set yet when they run, which is why the
handler above is usually the better choice.
</Callout>

## Folder layout and throughput

`directory` sets the key prefix:

| Value | Example prefix |
| --- | --- |
| `DATE` | `YYYY-MM-DD/` |
| `CHAT` | `1234567890/` |
| `DATE_CHAT` | `YYYY-MM-DD/1234567890/` |
| `CHAT_DATE` | `1234567890/YYYY-MM-DD/` |

Any other string is used as a literal folder name. Uploads queue up to 64
files, run two at a time and start at most two per second, so a busy session
queues work instead of uploading inline.

## Who can read `cloudUrl`

`public: false` keeps the object private, and the URL won't open without your
provider's credentials or a signed URL. `public: true` asks for a public object
URL; use it only when the bucket policy allows public reads, because anyone who
gets the URL can read the file. Signed-URL expiry and bucket policies are set
at your provider.

Test your provider with a real upload, a private read and a deletion before you
rely on it. Storing media in your own bucket gives you a place to apply
retention, access and residency rules, but it doesn't make you compliant with
any regulation by itself.
