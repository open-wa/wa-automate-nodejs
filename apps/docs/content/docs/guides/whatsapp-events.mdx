# Calendar events and RSVPs

WhatsApp events are calendar cards people can RSVP to. open-wa lets you send them, edit or cancel them, and read the responses, with seven methods and two listeners. Events need no license. The examples assume a `client` from `create()`.

## Create and update an event

```ts
const chatId = '447700900123@c.us';
const startTime = Math.floor(Date.now() / 1000) + 3600;

const eventId = await client.sendEvent(chatId, {
  name: 'Community meetup',
  startTime,
  endTime: startTime + 3600,
  description: 'Join us for a chat',
  location: 'London',
  extraGuestsAllowed: true,
});

await client.editEvent(eventId, {
  description: 'Updated meetup details',
  endTime: null,
});

const event = await client.getEvent(eventId);
console.log(event?.name, event?.isCanceled);

// If the meetup is canceled:
await client.cancelEvent(eventId);
```

Only the creator can edit or cancel an event. Omitted update fields keep their existing values; `endTime: null` removes the end time, and an empty description or location clears that field. A canceled event remains in history. Existing call links retain their call type when edited.

## Schedule a call

```ts
const callEventId = await client.sendEvent(chatId, {
  name: 'Planning call',
  startTime,
  endTime: startTime + 1800,
  callType: 'video', // or 'voice'
  isScheduledCall: true,
});
console.log((await client.getEvent(callEventId))?.joinLink);
```

`callType` creates a WhatsApp call link for the event, and `isScheduledCall` requires a call type. Pass `requireApproval` to make joiners wait for approval. If the link can't be created, `sendEvent` fails before anything is sent. A call link doesn't start a call, and older WhatsApp apps may not show a Join button.

`sendEvent` returns the message ID, and `editEvent`, `cancelEvent` and `respondToEvent` return `true` once the change is sent. None of these confirm delivery, so use `onAck` for delivery and read status. open-wa doesn't retry these calls; if the connection drops mid-send, check the chat and the current event before trying again.

## Read invitations and attendance

```ts
const firstPage = await client.getEvents(chatId, { limit: 20 });
const nextPage = firstPage.nextCursor
  ? await client.getEvents(chatId, { limit: 20, before: firstPage.nextCursor })
  : null;

const invitation = firstPage.events.find(event => !event.fromMe && !event.isCanceled);
if (invitation) {
  // Make this choice in your application or ask the user first.
  await client.respondToEvent(invitation.id, 'going');
  const attendance = await client.getEventResponses(invitation.id);
  console.log(attendance);
}
```

You can respond with `going`, `notGoing` or `maybe`, and reads can also return `unknown` for a value open-wa doesn't recognise. `getEventResponses` returns each participant's latest RSVP from the history this session has synced. The creator counts as attending only if they actually responded.

`getEvents` pages through the chat history this session has synced, newest first. Page limits are 1–100, and a cursor only works for the chat it came from. `getEvent` returns `null` for an event that isn't in that history, and edits fail when the event can't be found.

## Listen for event changes and RSVPs

```ts
const eventListener = client.onEvent(event => {
  console.log(event.id, event.name, event.isCanceled);
});

const attendanceListener = client.onEventResponse(response => {
  console.log(response.eventId, response.senderId, response.response);
});

// When the application no longer needs these subscriptions:
eventListener.off();
attendanceListener.off();
```

`onEvent` reports new and changed events, including ones this account sends, and `onEventResponse` reports RSVPs. Both can fire for older items while history loads, so keep response IDs and timestamps if you need to process each change once.

Event messages also carry the event as `message.event`. On `client.events`, the same updates arrive as `event.changed` with `{ event, ctx }` and `event.response` with `{ response, ctx }`.

## Times, validation and storage

Event start/end times and event creation timestamps are **Unix seconds**. RSVP timestamps are **milliseconds**. A new event needs a name and a future start time, and an end time can't be before the start.

To validate or store events yourself, `@open-wa/wa-automate` exports `EventInputSchema`, `EventUpdateSchema`, `WhatsAppEventSchema`, `EventResponseSchema`, `EventResponseTypeSchema`, `EventListOptionsSchema` and `EventPageSchema`, plus JSON serializers:

```ts
import {
  serializeWhatsAppEvent,
  deserializeWhatsAppEvent,
  serializeEventResponse,
  deserializeEventResponse,
} from '@open-wa/wa-automate';

const snapshot = await client.getEvent(eventId);
if (!snapshot) throw new Error('Event not found in synced history');
const savedEvent = serializeWhatsAppEvent(snapshot);
const restoredEvent = deserializeWhatsAppEvent(savedEvent);

const responses = await client.getEventResponses(eventId);
const savedResponses = responses.map(serializeEventResponse);
const restoredResponses = savedResponses.map(deserializeEventResponse);
```

The serializers validate the data and leave out message secrets and encryption keys, so the output is safe to store.

## API methods

| Method | Result | Purpose |
| --- | --- | --- |
| `sendEvent(to, event)` | `MessageId` | Send an event card. |
| `getEvent(eventId)` | `WhatsAppEvent \| null` | Read one event. |
| `getEvents(chatId, options?)` | `EventPage` | Page through synced event history. |
| `getEventResponses(eventId)` | `EventResponse[]` | Read the latest explicit RSVP per participant. |
| `editEvent(eventId, changes)` | `boolean` | Update an event created by this account. |
| `cancelEvent(eventId)` | `boolean` | Cancel an event created by this account. |
| `respondToEvent(eventId, response)` | `boolean` | Submit or change this account's RSVP. |

The [method reference](/docs/reference/client/whatsapp-events) has the Easy API routes, SocketClient examples, parameters and return types. The [listener reference](/docs/reference/client/events) lists `onEvent` and `onEventResponse`.
