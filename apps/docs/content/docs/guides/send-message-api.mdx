# Send a WhatsApp message

You need a WhatsApp account linked to open-wa on your own server, and a recipient that already has a chat with that account. Starting a chat with a new number needs a [license](/docs/licensing/pricing); replying to an existing chat doesn't. Both examples below send the same text with [`sendText`](/docs/reference/client/messages#sendtext), and a message ID in the response means WhatsApp accepted it.

## Send from Node.js

```ts title="send.mts"
import { create } from '@open-wa/wa-automate';

const client = await create({ sessionId: 'sender' });
const messageId = await client.sendText('447123456789@c.us', 'Hello from open-wa');
console.log('Submitted message', messageId);
await client.stop();
```

```bash
npm install @open-wa/wa-automate
npx tsx send.mts
```

Scan the QR code with WhatsApp on your phone the first time; open-wa keeps the login for later runs. The script prints `Submitted message true_447123456789@c.us_3EB0C7...` and the text appears in the chat. [Send your first message with the Node.js SDK](/docs/getting-started/custom-code) walks through the setup in more detail.

## Send over HTTP

With the [Easy API](/docs/getting-started/easy-api) running on the machine that holds the session (see [start the Easy API](#start-the-easy-api)), `POST` the same fields to `/api/messages/sendText` from any language:

```bash
curl --fail-with-body http://localhost:8080/api/messages/sendText \
  -H "Content-Type: application/json" \
  -H "X-API-Key: your-api-key" \
  -d '{"to":"447123456789@c.us","content":"Hello from open-wa"}'
```

A successful send returns HTTP 200 with the message ID in `data`:

```json
{
  "success": true,
  "data": "true_447123456789@c.us_3EB0C7D5E4A1B2"
}
```

## Find the recipient chat ID

open-wa sends to a chat ID, not a bare phone number. For a person, write the full international number without `+`, spaces or dashes, then add `@c.us`.

| Recipient | Chat ID |
| --- | --- |
| UK number +44 7123 456789 | `447123456789@c.us` |
| Group | The `@g.us` ID from the group metadata |
| Sender of an incoming message | The exact `message.from` value |

When you reply to an incoming message, reuse `message.from` unchanged, because it can end in `@lid`. The [chat ID primer](/docs/guides/chatid-primer) covers every ID type.

## What the message ID tells you

`sendText` resolves to the message ID once WhatsApp accepts the message. That confirms the send, not delivery, so subscribe to [`onAck`](/docs/reference/client/events#ack) before sending if you need delivery and read states (see [acknowledgements](/docs/guides/messages#acknowledgements)). Over HTTP, the same updates arrive as `ack.changed` events; the [webhook payload](/docs/reference/event-contracts/generated/webhook_ack_changed) shows their shape.

If the send fails, `sendText` throws a `SendTextError` with a `code` and an `outcome`. An `outcome` of `not_sent` is safe to retry after fixing the cause, for example `LICENSE_REQUIRED` for a new number. An `outcome` of `unknown` means the message may already be in the chat, so check before sending again; open-wa never retries `sendText` for you.

## Start the Easy API

The HTTP example needs the Easy API running and linked. Start it on the machine that holds the session:

```bash
npx @open-wa/wa-automate --session-id sender --api-key "your-api-key"
```

It listens on `http://localhost:8080` by default. Scan the QR code in the terminal, and send once `/health` reports `"connected": true`.

A failed send returns an error body instead of `success`. For example, a first message to a number without a license returns HTTP 500 with:

```json
{
  "error": "Starting a chat with a new number requires an applied restricted or premium license."
}
```

The same request works from any language. This example uses Python with `requests`:

```python
import requests

response = requests.post(
    "http://localhost:8080/api/messages/sendText",
    headers={"X-API-Key": "your-api-key"},
    json={"to": "447123456789@c.us", "content": "Hello from open-wa"},
    timeout=30,
)
response.raise_for_status()
print(response.json()["data"])
```

The Easy API also serves an API explorer at `http://localhost:8080/api-docs/` (on your machine), where you can look up the request body for every method.

## Reply to a received message

To reply in the same chat, send to the sender's chat ID. To quote the message, pass its ID to `reply`:

```ts
client.onMessage(async (message) => {
  if (message.body === 'ping') {
    await client.reply(message.from, 'pong', message.id);
  }
});
```

The [support bot recipe](/docs/build/support-bot) builds on this into a complete bot, and [receive messages](/docs/guides/receive-messages) covers listening over HTTP and webhooks.

## Troubleshooting

| Problem | Cause | Fix |
| --- | --- | --- |
| The request returns `401` | The `X-API-Key` header doesn't match the configured key. | Send the same key you gave to `--api-key` or `WA_API_KEY`. |
| The request returns `503` | The session isn't ready yet. | Wait until `/health` reports `session.ready: true`, then retry. |
| The send fails for a new number | The account has no chat with that number. | Apply a license, or let the recipient message you first. |
| The error has `outcome: 'unknown'` | open-wa couldn't confirm the result. | Check the chat before sending again. |
| The number never receives the message | The chat ID format is wrong. | Remove `+`, spaces and dashes, and add `@c.us`. |

<Callout type="warning">
WhatsApp can restrict an account that sends many messages to new contacts. Message only people who expect to hear from you, and follow the [rate limits](/docs/operations/rate-limits).
</Callout>
