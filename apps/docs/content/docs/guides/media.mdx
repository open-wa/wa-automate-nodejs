# Send and receive media

[`sendFile(to, input, filename?, options?)`](/docs/reference/client/messages#sendfile) and [`sendImage`](/docs/reference/client/messages#sendimage) send images, videos, audio and documents from a local path, URL, data URL, base64 string or `Buffer`. The filename is optional; open-wa infers it from the path, URL or MIME type. Captions and quoted-message IDs go in `options`.

```ts
await client.sendImage(chatId, './photo.jpg', 'photo.jpg', { caption: 'Hello' });
await client.sendFile(chatId, './clip.mp4', 'clip.mp4', { caption: 'Watch this' });
await client.sendFile(chatId, './report.pdf', 'report.pdf', { caption: 'Report' });
await client.sendAudio(chatId, './sound.mp3');
await client.sendPtt(chatId, './voice.ogg');
await client.sendVideoAsGif(chatId, './loop.mp4');
```

Each call resolves to the sent message's ID. [`sendAudio`](/docs/reference/client/messages#sendaudio), [`sendPtt`](/docs/reference/client/messages#sendptt) and [`sendVideoAsGif`](/docs/reference/client/messages#sendvideoasgif) list their own options.

Over the Easy API, paths refer to files on the machine running the Easy API, so send a reachable URL or a complete data URL from anywhere else.

## Choose how the media appears

The `type` option picks the presentation and decides which other options apply. Unknown fields and invalid combinations are rejected before anything is sent. The `MediaSendOptions` type is exported from `@open-wa/schema`.

| `type` | Options | Behavior |
| --- | --- | --- |
| Omitted or `auto` | `caption`, `quotedMsgId`, `viewOnce` | Detects the MIME type. View once needs an image or video. |
| `image` | `caption`, `quotedMsgId`, `viewOnce` | Requires an image. |
| `video` | `caption`, `quotedMsgId`, `viewOnce`, `isGif`, `videoNote` | Requires a video. GIFs and video notes need MP4. |
| `audio` | `quotedMsgId`, `ptt`, `viewOnce` | Requires audio. View once needs `ptt: true`. |
| `document` | `caption`, `quotedMsgId` | Sends any file as a document, including images, videos and audio. |

open-wa uploads the media as you supply it, without transcoding, cropping or shortening it. WhatsApp's size limits still apply. A returned message ID confirms the send, not delivery, so use `onAck` for delivery and check the chat before retrying an uncertain send.

## View once

```ts
await client.sendFile(chatId, './photo.jpg', 'photo.jpg', {
  type: 'image', viewOnce: true, quotedMsgId: messageId,
});
await client.sendFile(chatId, './clip.mp4', 'clip.mp4', { type: 'video', viewOnce: true });
await client.sendPtt(chatId, './voice.ogg', { viewOnce: true });
```

With `sendFile`, a view-once voice note is `{ type: 'audio', ptt: true, viewOnce: true }`. Documents and ordinary audio can't be view once.

## Video notes and GIFs

```ts
await client.sendFile(chatId, './square-note.mp4', 'note.mp4', { type: 'video', videoNote: true });
await client.sendFile(chatId, './loop.mp4', 'loop.mp4', {
  type: 'video', isGif: true, caption: 'Looping clip',
});
```

A video note shows as a circle. Supply a square MP4 of 60 seconds or less; video notes can't have a caption or be GIFs. A GIF is an MP4 that loops, and it can't be view once. For voice notes, send prepared audio such as Ogg Opus.

## Send media as a document

```ts
await client.sendFile(chatId, './photo.jpg', 'original.jpg', {
  type: 'document', caption: 'Original file', quotedMsgId: messageId,
});
```

Documents keep the file's MIME type and filename, and the caption is separate from the filename.

## Send from a URL that needs authentication

[`sendFileFromUrl(to, url, filename, options, headers)`](/docs/reference/client/messages#sendfilefromurl) downloads the file with the headers you pass, then sends it with the same presentation options. The URL must return the file itself.

```ts
await client.sendFileFromUrl(
  chatId,
  'https://files.example.com/invoices/123.pdf',
  'invoice-123.pdf',
  { type: 'document', caption: 'Invoice 123' },
  { Authorization: `Bearer ${process.env.FILE_API_TOKEN}` },
);
```

## Data URLs and MIME types

```ts
import { readFile } from 'node:fs/promises';

const buffer = await readFile('./photo.jpg');
const dataUrl = `data:image/jpeg;base64,${buffer.toString('base64')}`;
await client.sendImage(chatId, dataUrl, 'photo.jpg', { viewOnce: true });
```

Use the file's real MIME type. For `application/octet-stream`, open-wa falls back to the filename extension or the file's signature, and an unrecognised file goes as a document. Base64 makes a file about a third larger and holds it in memory, so stream large files from a URL instead.

## Save incoming media

[`client.decryptMedia(message)`](/docs/reference/client/media#decryptmedia) returns the media as a data URL, ready to send back or decode:

```ts
client.onMessage(async (message) => {
  if (!message.mimetype) return;
  const dataUrl = await client.decryptMedia(message);
  const buffer = Buffer.from(dataUrl.split(',')[1] ?? '', 'base64');
  console.log(message.mimetype, buffer.length);
});
```

To get raw bytes without the data URL step, use `decryptMedia` from `@open-wa/decrypt`, which returns a `Buffer`. This example writes each file with an extension that matches its MIME type:

```ts
import { mkdir, writeFile } from 'node:fs/promises';
import path from 'node:path';
import mime from 'mime-types';
import { decryptMedia } from '@open-wa/decrypt';

client.onMessage(async (message) => {
  if (!message.mimetype) return;

  const buffer = await decryptMedia(message);
  const extension = mime.extension(message.mimetype) || 'bin';
  await mkdir('media', { recursive: true });
  await writeFile(path.join('media', `${message.id}.${extension}`), buffer);
});
```

For object storage, upload the same bytes and keep the MIME type as metadata, or let the [S3 media integration](/docs/guides/s3-media) do it for every message. For two-way voice-note conversations, see the [Voxtral voice assistant](/docs/guides/voxtral).

Media links expire, so save media when it arrives. Older messages that weren't downloaded at the time may no longer be retrievable.

## Send a sound sticker

[`sendSoundSticker(to, sticker, sound, options?)`](/docs/reference/client/messages#sendsoundsticker) sends a sticker with a short sound the recipient can play. Both inputs take a local path, URL, data URL, base64 string or `Buffer`.

```ts
await client.sendSoundSticker(chatId, './muffin.png', './chime.ogg');
```

The image is resized into a square sticker for you. The sound isn't converted, so supply an Ogg Opus or M4A clip of at most 1 MB; anything else, such as MP3, is rejected before sending. With ffmpeg, `ffmpeg -i clip.mp3 -c:a libopus -ac 1 chime.ogg` produces a clip that works. Keep clips to a few seconds, and pass `{ quotedMsgId }` to send the sticker as a reply.

Sound stickers are new in WhatsApp. People on an app version without them see an ordinary sticker, and the method throws if the sending account doesn't have them yet.

## Test what you'll run

Media depends on more than the method call: remote URLs must be reachable from the open-wa host, data URLs keep the whole file in memory, and video, GIF, sticker and voice-note sends depend on the browser you run. Test the exact types, sizes and browser you plan to deploy before relying on a media flow.
