# Cloudflare session proxy

The Cloudflare session proxy lets a local Easy API session make an outbound WebSocket connection to a Cloudflare Worker. Remote consumers call the Worker, so the local machine needs no inbound port. The Worker makes the Easy API reachable from the internet, so the session must have an Easy API key. The session does not connect to the proxy without one.

## Topology and limits

```text
Remote consumer --HTTPS/WebSocket--> Cloudflare Worker --Durable Object--> local TunnelClient --HTTP--> Easy API
```

The Worker authenticates the session's connection to `/sessions/:sessionId/upstream` with `UPSTREAM_TOKEN`. It forwards all other HTTP requests to the session unchanged, so the session's Easy API key or MCP OAuth sign-in decides access. `CONSUMER_TOKEN` protects only the `/connect` WebSocket that `@open-wa/socket-client` uses.

The Worker routes each session ID to one Durable Object and streams requests to the session and responses from it. The session must start a response within 30 seconds, or the caller receives `504`. After the response starts, the body can continue for as long as needed, so MCP event streams and large media files pass through. When the session is not connected, the Worker returns `503 Session offline` with the time the session disconnected.

Only one instance of a session can be connected. When a second instance connects with the same session ID, it replaces the first one, and the first one stops and logs an error.

The Durable Object hibernates while the connection is idle, which keeps compute low, but Worker requests, Durable Objects, storage and egress are still billed by Cloudflare. Check [Cloudflare Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) for the account and plan you use.

## Deploy from an empty directory

The Worker is not published to npm, so deploy it from a checkout of the open-wa repository.

```bash
git clone https://github.com/open-wa/wa-automate-nodejs.git
cd wa-automate-nodejs
corepack enable
pnpm install
cd packages/cf-proxy
pnpm exec wrangler login
pnpm exec wrangler whoami
```

`pnpm exec wrangler whoami` must show the Cloudflare account that will own the Worker and its Durable Object namespace.

The checked-in `wrangler.jsonc` is the binding and migration required by the entrypoint:

```jsonc
{
  "name": "open-wa-proxy",
  "main": "src/index.ts",
  "compatibility_date": "2024-03-20",
  "durable_objects": {
    "bindings": [{
      "name": "SESSION_TUNNEL",
      "class_name": "SessionTunnel"
    }]
  },
  "migrations": [{
    "tag": "v1",
    "new_classes": ["SessionTunnel"]
  }]
}
```

Set both Worker secrets without putting their values in the repository or shell history:

```bash
export WA_PROXY_TOKEN="$(openssl rand -hex 32)"
export PROXY_CONSUMER_TOKEN="$(openssl rand -hex 32)"

printf '%s' "$WA_PROXY_TOKEN" | pnpm exec wrangler secret put UPSTREAM_TOKEN
printf '%s' "$PROXY_CONSUMER_TOKEN" | pnpm exec wrangler secret put CONSUMER_TOKEN
pnpm exec wrangler deploy
```

Record the deployed `workers.dev` hostname, for example `https://open-wa-proxy.<account>.workers.dev`. The local session needs the upstream token (`WA_PROXY_TOKEN`, which the CLI reads). Only `@open-wa/socket-client` consumers need the consumer token (`PROXY_CONSUMER_TOKEN` is this page's shell variable).

## Deploy from an existing checkout

Contributors who already have the repository use the same entrypoint and binding from the repository root:

```bash
pnpm install
pnpm --filter @open-wa/cf-proxy exec wrangler whoami
pnpm --filter @open-wa/cf-proxy exec wrangler deploy
```

Run `secret put` again only when rotating a value. The Worker code reads the secrets by the exact names `UPSTREAM_TOKEN` and `CONSUMER_TOKEN`. To rename them, change the Worker code.

## Attach a local session

Start the session on the machine that holds the WhatsApp login. Easy API starts, opens the upstream WebSocket when the API listens, and reconnects after a disconnect.

```bash
export WA_PROXY_HOST='https://open-wa-proxy.<account>.workers.dev'
npx @open-wa/wa-automate --session-id sales \
  --api-key "$WA_API_KEY" \
  --proxy-host "$WA_PROXY_HOST" \
  --proxy-token "$WA_PROXY_TOKEN"
```

The proxy flags are optional when `WA_PROXY_HOST` and `WA_PROXY_TOKEN` are set. `@open-wa/cli` takes the same flags.

The session connects to `/sessions/sales/upstream` and sends the upstream token in the `Authorization` header. The Worker does not run WhatsApp or the browser. They stay on the local machine and still determine session readiness and Easy API behavior.

## Consume the session

Call the Easy API through the Worker with the Easy API key, as you would call it locally:

```bash
curl -i -X POST \
  "${WA_PROXY_HOST}/sessions/sales/api/sendText" \
  -H "X-API-Key: $WA_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"args":["1234567890@c.us","Hello through Cloudflare"]}'
```

The Worker forwards headers such as `Authorization` and `X-API-Key` to the local Easy API without checking them. A caller without a valid key receives the local API's `401` response.

Node clients can use the compatibility URL, which selects the tunnel transport in `@open-wa/socket-client`:

```ts
import { SocketClient } from '@open-wa/socket-client';

const client = await SocketClient.connect(
  `cf-proxy://open-wa-proxy.<account>.workers.dev?sessionId=sales&token=${encodeURIComponent(process.env.PROXY_CONSUMER_TOKEN)}`,
);
console.log(await client.getHostNumber());
```

## One hostname per session

MCP clients such as ChatGPT sign in with OAuth, and OAuth needs the MCP server at the root of a hostname. A `/sessions/sales` path prefix does not work for them. Give each session its own hostname instead:

1. Add a Worker route for `*.wa.example.com/*` on your Cloudflare zone, and a proxied DNS record for `*.wa.example.com`.
2. Set the Worker variable `ROUTER_DOMAIN` to `wa.example.com` and deploy.
3. Start the session with `--session-id sales`. The Worker then sends requests for `https://sales.wa.example.com` to that session at the root path.

The session ID must use only lowercase letters, digits and hyphens to work as a hostname. The Worker tells the session its public hostname, so MCP OAuth uses `https://sales.wa.example.com` without an `oauth.publicUrl` setting.

## Custom domain

Keep `workers.dev` until the Worker works end to end. When a Cloudflare zone is ready, add a Worker custom domain or route in the Cloudflare dashboard or Wrangler configuration, deploy again, and replace `WA_PROXY_HOST` with the resulting `https://` hostname. The local session and remote consumers must use the same Worker hostname; a DNS record pointing at another Worker will produce a valid-looking but incorrect endpoint.

## Troubleshooting

| Symptom | Command or observation | Expected result | Next action |
| --- | --- | --- | --- |
| Worker deploy fails before creating a route | `pnpm exec wrangler whoami` and inspect `wrangler.jsonc` | The account is authenticated and `SESSION_TUNNEL` binds `SessionTunnel`. | Log in to the intended account and deploy from `packages/cf-proxy`, or fix the binding/migration file. |
| The session log reports unauthorized upstream | Read the session log and run `pnpm exec wrangler secret list` | The session log says it connected upstream, and the secret list contains `UPSTREAM_TOKEN`. | Set that secret to the exact value of `--proxy-token` or `WA_PROXY_TOKEN`, then restart the CLI. |
| The session log says it is not connecting to the session proxy | Read the error line in the session log | The session has an Easy API key. | Start the session with `--api-key` or set `apiKey` in the configuration. |
| Caller gets `401` from the Easy API | Send the `curl` command again with `X-API-Key` | The key matches the session's `--api-key`. | Send the session's Easy API key, or sign in with OAuth for MCP. |
| Caller gets `503 Session offline` | Check the session log for `Connected upstream for session sales` | The upstream WebSocket is open for the same session ID. | Start the session with the proxy flags, match `--session-id` to the URL, and check the session is ready. |
| The session log says another instance connected | Check for a second process with the same session ID | One process runs per session ID. | Stop the other process, then restart this one. |
| Caller gets `504` | Call the same path against `http://localhost:8080` | The local API starts its response within 30 seconds. | Fix the local API, browser, or Easy API key before you investigate Cloudflare routing. |
