# Configuration and CLI

Use this guide to configure runtime parameters, command-line flags, environment variables, and plugin settings for open-wa.

## Common configuration properties

Pass options to `createClient()` or export them from `wa.config.mjs` to customize runtime behavior:

- `sessionId`: Stable identifier for session storage
- `userDataDir`: Path to the persistent browser profile directory
- `headless`: Run the browser in the background (`true`) or visibly (`false`)
- `useChrome` or `executablePath`: Specify a custom Chrome or Chromium binary
- `qrTimeout` and `authTimeout`: Timeouts for QR generation and session authentication (in milliseconds)
- `maxQr`: Maximum number of QR code refresh cycles
- `cacheEnabled`: Enable or disable page cache
- `licenseKey`: Commercial license key for enterprise features
- `proxyServerCredentials`: Outbound HTTP/SOCKS proxy configuration
- `linkCode`: Phone number string for numeric link-code authentication

## Basic configuration example

```ts
import { createClient } from '@open-wa/wa-automate';

const client = await createClient({
  sessionId: 'sales',
  useChrome: true,
  headless: true,
  qrTimeout: 0,
  authTimeout: 60,
});
```

## Configuration file discovery order

When launched without an explicit `--config` path, the CLI searches for configuration files in the current working directory in the following order:

1. The `wa` key in `package.json`
2. `wa.config.js`
3. `wa.config.cjs`
4. `wa.config.mjs`
5. `wa.config.ts`
6. `wa.config.mts`
7. `wa.config.cts`
8. `wa.config.json`
9. `.warc`
10. `.warc.json`
11. `cli.config.js` (legacy compatibility)
12. `cli.config.json` (legacy compatibility)

The first matching configuration file is loaded. Use `--config ./path/to/config` to explicitly specify a file path.

Settings are merged with the following precedence (highest priority first):

1. Programmatic overrides (in tests and embedded code)
2. CLI arguments
3. `WA_*` environment variables
4. Configuration file values
5. Schema default values

## Environment variables

Configure open-wa using environment variables prefixed with `WA_`. Snake-case variable names automatically map to camelCase configuration keys (for example, `WA_SESSION_ID` maps to `sessionId`).

Common environment variables:

| Environment variable | Configuration property | Description |
| --- | --- | --- |
| `WA_SESSION_ID` | `sessionId` | Unique session name |
| `WA_PORT` | `port` | Easy API server port |
| `WA_HOST` | `host` | Easy API bind host |
| `WA_API_KEY` | `apiKey` | Authentication key for API requests |
| `WA_USER_DATA_DIR` | `userDataDir` | Path to persistent browser profile storage |
| `WA_LICENSE_KEY` | `licenseKey` | Commercial license key |
| `WA_LINK_CODE` | `linkCode` | Target phone number for link-code pairing |
| `WA_HEADLESS` | `headless` | Controls headless browser execution |
| `WA_USE_CHROME` | `useChrome` | Prefer installed system Chrome binary |
| `WA_QR_TIMEOUT` | `qrTimeout` | Timeout for QR generation |
| `WA_AUTH_TIMEOUT` | `authTimeout` | Timeout for user login completion |
| `WA_WEBHOOK` | `webhook` | Target URL for event webhooks |
| `WA_PLUGINS` | `plugins` | JSON array of plugin package names or paths |
| `WA_PLUGIN_CONFIG` | `pluginConfig` | JSON object containing plugin-specific options |

## Common CLI options

```bash
# Network options
--port 8080
--api-key "YOUR_SECURE_KEY"
--host "0.0.0.0"

# Session identity
--session-id sales
--link-code "447123456789"

# Process management
--pm2

# Commercial license
--license-key "YOUR_LICENSE_KEY"

# Chat execution sandboxing
--sandbox-chats
--sandbox-isolation container
```

### Chat execution sandboxing

The `sandboxChats` option isolates dynamic code and tools executed via `executeInChatSandbox`:

```ts
export default defineConfig({
  sandboxChats: {
    isolation: 'container', // 'worker' | 'process' | 'container'
    timeoutMs: 30_000,
    idleTimeoutMs: 300_000,
    memoryMb: 256,
    concurrency: 1,
    filesystem: 'none', // 'none' | 'read-only' | 'workspace'
    network: 'none', // 'none' | 'allowlist'
    networkAllowlist: [],
    env: 'none',
    capabilities: ['sendText'],
  },
});
```

Container isolation provides a strong security boundary for untrusted code. Process isolation enforces time, memory, and output limits within a child process. Worker isolation provides thread-level isolation for trusted workloads.

## CLI option reference

| Option | Configuration key | Description |
| --- | --- | --- |
| `--port 8080`, `-p 8080` | `port` | Easy API server port |
| `--api-key "YOUR_SECURE_KEY"`, `-k` | `apiKey` | API key required in `X-API-Key` headers |
| `--session-id sales` | `sessionId` | Names the session and isolates disk credentials |
| `--webhook "https://..."`, `-w` | `webhook` | Webhook URL for event delivery |
| `--pm2` | Process manager | Launches the process under PM2 |
| `--license-key "KEY"`, `-l` | `licenseKey` | Commercial license key |
| `--link-code "447123456789"` | `linkCode` | Initiates eight-digit pairing code authentication |
| `--host "0.0.0.0"`, `-h` | `host` | Local bind address for Easy API |
| `--sandbox-chats` | `sandboxChats: true` | Enables isolation for per-chat tool calls |
| `--sandbox-isolation process` | `sandboxChats.isolation` | Sets isolation model (`worker`, `process`, `container`) |

## CLI to schema mapping

Command-line arguments map directly to schema properties. For example:

```bash
npx @open-wa/wa-automate@alpha \
  --session-id sales \
  --port 8080 \
  --api-key "$WA_API_KEY" \
  --license-key "$WA_LICENSE_KEY" \
  --link-code "447123456789"
```

corresponds to the following configuration object:

```ts
export default {
  sessionId: 'sales',
  port: 8080,
  apiKey: process.env.WA_API_KEY,
  licenseKey: process.env.WA_LICENSE_KEY,
  linkCode: '447123456789',
};
```

## Plugin configuration array

Use the `plugins` array to load extensions into the runtime process:

```ts
export default {
  plugins: [
    '@open-wa/integration-webhook',
    '@open-wa/integration-chatwoot',
    './plugins/my-local-plugin',
  ],
};
```

Each entry is a package name or local file path exporting a valid open-wa plugin definition.

## Plugin-specific configuration

Provide options for each loaded plugin in the `pluginConfig` object, keyed by the plugin's `meta.name`:

```ts
export default {
  plugins: ['@open-wa/integration-webhook', './plugins/moderation'],
  pluginConfig: {
    webhook: {
      url: 'https://example.com/webhook',
      headers: {
        'X-Webhook-Secret': process.env.WEBHOOK_SECRET,
      },
    },
    moderation: {
      enabled: true,
      apiKey: process.env.MODERATION_API_KEY,
    },
  },
};
```

## Complete plugin configuration example

```ts
import { defineConfig } from '@open-wa/config';

export default defineConfig({
  sessionId: 'support',
  port: 8080,
  host: '0.0.0.0',
  apiKey: process.env.WA_API_KEY,
  plugins: [
    '@open-wa/integration-webhook',
    './plugins/internal-audit-plugin',
  ],
  pluginConfig: {
    webhook: {
      url: process.env.WA_WEBHOOK,
      headers: {
        'X-Webhook-Secret': process.env.WEBHOOK_SECRET,
      },
    },
    'internal-audit': {
      enabled: true,
      logLevel: 'info',
    },
  },
});
```

## Manage secrets securely

Do not commit API keys, secrets, or authentication tokens into version control:

- Store credentials in an external `.env` file added to `.gitignore`.
- In production, inject secrets via environment variables or a secrets manager.
- Restrict file system permissions on session profile directories (`_IGNORE_*`).
