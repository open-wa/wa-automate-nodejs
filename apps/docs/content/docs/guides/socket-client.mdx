# SocketClient

Use `@open-wa/socket-client` when the WhatsApp session runs in an Easy API on another machine or process and your Node.js app wants the same methods and listeners as the SDK. Commands travel as HTTP requests and events arrive over Server-Sent Events (SSE).

## Install and connect

Install the client and `tsx` in the Node.js app that will consume Easy API:

```bash
npm install @open-wa/socket-client
npm install --save-dev tsx
```

Start or locate an Easy API session, then connect using its base URL. Pass the API key when the server requires one:

```ts
import { SocketClient } from '@open-wa/socket-client';

const client = await SocketClient.connect('http://localhost:8080', process.env.WA_API_KEY);
```

Keep the key in server-side configuration. The client sends it as `X-API-Key` on command requests and as `api_key` on the SSE URL because the standard `EventSource` API cannot set custom headers.

## Run a consumer

Save this as `consumer.ts`. It logs incoming messages and does not send a WhatsApp message:

```ts
import { SocketClient } from '@open-wa/socket-client';

const url = process.env.EASY_API_URL;
const apiKey = process.env.WA_API_KEY;
if (!url) throw new Error('Set EASY_API_URL to the Easy API base URL');

const client = await SocketClient.connect(url, apiKey);

client.socket.on('connect', () => console.log('Easy API event stream connected'));
client.socket.on('disconnect', (reason) => console.warn('Event stream disconnected:', reason));
client.socket.on('connect_error', (error) => console.error('Event stream connection failed:', error));

await client.listen('onMessage', (message) => {
  console.log('Incoming message:', message.from, message.body);
});

console.log('Listening for messages; press Ctrl-C to stop');
process.once('SIGTERM', () => {
  client.close();
  process.exit(0);
});
```

Run it with the address of your Easy API instance:

```bash
EASY_API_URL='http://localhost:8080' npx tsx consumer.ts
```

`EASY_API_URL` is this example's own variable. If the Easy API has an API key, also set `WA_API_KEY` to the same value. For any example that calls `sendText`, replace the destination with a chat you control and run it only when you intend to send that message.

## Call methods

The client has every Easy API method. The names and the argument order are the same as on the SDK `Client`, so `client.sendText(chatId, text)` is the same call in each place. TypeScript checks the arguments, and your editor shows the parameters and the description of each method.

Pass the arguments in order, or pass one object of named parameters:

```ts
const chatId = '447700900123@c.us';

const messageId = await client.sendText(chatId, 'Hello from SocketClient');
await client.sendText({ to: chatId, content: 'Hello from SocketClient' });

await client.sendImage(chatId, 'https://example.com/receipt.png', 'receipt.png', { caption: 'Receipt attached' });
const chats = await client.getAllChats();
```

`ask()` calls a method by name. It takes the same named parameters, and it is the form to use when your code selects the method name at run time:

```ts
const sameMessageId = await client.ask('sendText', { to: chatId, content: 'Hello from SocketClient' });
```

Replace the chat ID with a chat you control before you run a send example. The [API reference](/docs/reference/client) lists each method with its parameters.

## Listen for events

Each listener of the SDK `Client` is a method on the socket client. The callback receives the same value that the SDK listener of that name delivers, so `onMessage` receives the message:

```ts
import { SocketClient, type Message } from '@open-wa/socket-client';

const client = await SocketClient.connect('http://localhost:8080', process.env.WA_API_KEY);

await client.onMessage((message) => console.log(message.from, message.body));
await client.onStateChanged((state) => console.log('Session state:', state));
```

`listen()` registers the same listeners by name and returns an ID. Pass that ID to `stopListener()` to remove the callback. The parameter of the callback is typed from the listener name, and a type annotation is optional:

```ts
const listenerId = await client.listen('onMessage', async (message: Message) => {
  if (message.body === 'ping') await client.sendText(message.from, 'pong');
});

client.stopListener('onMessage', listenerId);
```

`listen()` accepts the listener name as a string or as a `SimpleListener` member, for example `SimpleListener.Message`.

| Listener | The callback receives |
| --- | --- |
| `onMessage`, `onAnyMessage` | The message |
| `onAck` | The message with its new `ack` value |
| `onStateChanged` | The new session state, for example `READY` |
| `onLogout` | `{ reason, timestamp }` |
| `onGlobalParticipantsChanged` | The participant change. `onParticipantsChanged(groupId, callback)` limits it to one group |
| `onPollVote` | The poll vote |
| `onEvent`, `onEventResponse` | The WhatsApp event, or the response to one |
| `onInteractiveResponse`, `onFormResponse` | The interactive response |
| `onIncomingCall`, `onCallState` | The call, with its controls |

The `client.socket` event hooks report the SSE connection. They do not indicate whether an individual command succeeded.

## Reconnect and shutdown

`SocketClient.connect()` waits for the first SSE connection before resolving. The underlying event source retries a dropped stream; listeners are registered again after it reconnects. HTTP command calls can fail independently, so handle command errors at the call site.

If you need to initiate a reconnect yourself, call `reconnect()`. Use `close()` or `disconnect()` when stopping the consumer:

```ts
try {
  await client.reconnect();
} catch (error) {
  console.error('Could not reconnect:', error);
}

client.close();
```

If the first stream connection fails, `connect()` rejects with `Unable to establish SSE connection`. A stopped event stream does not by itself mean the WhatsApp session stopped; check Easy API health before restarting its runtime.

## Cloudflare session proxy

For remote access without opening an inbound port to the Easy API, use the [Cloudflare session proxy](/docs/guides/cf-proxy). `SocketClient.connect()` accepts its `cf-proxy://` URL format.

## Move from v4

v4 used socket.io and v5 uses HTTP and SSE, so a v4 socket client cannot connect to a v5 Easy API. Install the v5 `@open-wa/socket-client`, at the same version as the Easy API you connect to.

Your code keeps the form it had in v4. `SocketClient.connect(url, apiKey)`, `client.listen('onMessage', callback)`, `client.onMessage(callback)` and direct calls such as `client.sendText(chatId, text)` take the same arguments, and the listener callbacks receive the same values. TypeScript reports a method that v5 does not have.

## Security

The consumer can call Easy API methods and receive session events. It has no access to the browser. Treat the API key as a server secret and restrict network access to the API.
