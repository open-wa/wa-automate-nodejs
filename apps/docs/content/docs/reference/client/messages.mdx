# Messages


## `sendText`

Send a text message to a chat. Starting a chat with a number that has never messaged you needs a Restricted or Premium license.

<ReferenceCode>

```ts
client.sendText(to: string, content: string, options?: unknown): Promise<MessageId>
```

</ReferenceCode>

Leave out `options`: `sendText` ignores it, and neither the SDK nor HTTP needs it. For a quoted reply use `reply(to, content, messageId)`, and for mentions use `sendTextWithMentions`.

<h3 id="sendtext-usage" className="scroll-m-28">Usage</h3>

<InterfaceTabs>
  <InterfaceTab value="SDK">

<ReferenceCode>

```ts
const messageId = await client.sendText('447123456789@c.us', 'Hello from open-wa');
console.log('Message ID:', messageId);
```

</ReferenceCode>

  </InterfaceTab>
  <InterfaceTab value="SocketClient">

<ReferenceCode>

```ts
import { SocketClient } from '@open-wa/socket-client';

const client = await SocketClient.connect('http://localhost:8080', 'YOUR_API_KEY');
const messageId = await client.sendText("447123456789@c.us", "Hello, world!");
console.log('Message ID:', messageId);
```

</ReferenceCode>

  </InterfaceTab>
  <InterfaceTab value="HTTP">

<ReferenceCode>

```bash
curl -X POST "http://localhost:8080/api/messages/sendText" \
  -H "content-type: application/json" \
  -H "x-api-key: YOUR_API_KEY" \
  --data '{
    "to": "447123456789@c.us",
    "content": "Hello, world!"
  }'
```

</ReferenceCode>

Response:

<ReferenceCode>

```json
{
  "success": true,
  "data": "true_447123456789@c.us_9C4D0965EA5C09D591334AB6BDB07FEB"
}
```

</ReferenceCode>

  </InterfaceTab>
</InterfaceTabs>

<h3 id="sendtext-parameters" className="scroll-m-28">Parameters</h3>

| Parameter | Type | Description |
| --- | --- | --- |
| `to` | `string` | Recipient chat ID. The target chat for a send operation. Also accepts `chatId`. |
| `content` | `string` | Message content. Also accepts `body`, `message`, `text`. |
| `options` | `unknown` | Optional. Not used. Leave it out; use reply() for quoted replies and sendTextWithMentions() for mentions. sendText ignores this value. |

<h3 id="sendtext-returns" className="scroll-m-28">Returns</h3>

Resolves to [`MessageId`](/docs/reference/client/return-types#messageid).

The ID means WhatsApp accepted the message, not that it was delivered or read. On failure the SDK throws `SendTextError`, exported by `@open-wa/wa-automate`. Its `code` is `INVALID_ARGUMENT`, `LICENSE_REQUIRED`, `SEND_REJECTED`, `INVALID_SEND_RESULT` or `SEND_FAILED`, and its `outcome` is `not_sent` or `unknown`. An `unknown` outcome means the message may already have been sent, so check the chat before you retry. The client never retries on its own.

**HTTP:** `POST /api/messages/sendText`, or `/api/sendText`. **Also named:** `messages.sendText`.


## `sendImage`

Send an image or video, or any other media file, as a WhatsApp attachment. Options set the caption, view once, GIF playback or a round video note. Media is sent as is, without conversion. Resolves to the send result, not a delivery receipt.

<ReferenceCode>

```ts
client.sendImage(
  to: string,
  file: string | Buffer,
  filename?: string,
  options?: MediaSendOptions,
): Promise<MessageIdReturn | boolean>
```

</ReferenceCode>


</ReferenceCode>


</ReferenceCode>

  </InterfaceTab>

```bash
curl -X PUT "http://localhost:8080/api/messages/unstar" \
  -H "content-type: application/json" \
  -H "x-api-key: YOUR_API_KEY" \
  --data '{
    "messageId": "false_447123456789@c.us_9C4D0965EA5C09D591334AB6BDB07FEB"
  }'
```

</ReferenceCode>

Response:

<ReferenceCode>

```json
{
  "success": true,
  "data": true
}
```

</ReferenceCode>

  </InterfaceTab>
