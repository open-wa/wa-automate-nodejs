# Custom code

Use this guide when your Node.js application needs to embed the open-wa runtime directly instead of connecting to a separate Easy API server.

## Install the package and a driver

<PackageManagerTabs command="@open-wa/wa-automate @open-wa/driver-puppeteer" />

If your environment has strict native module installation permissions, pass `--unsafe-perm` only when required by your system.

## Runtime entry point

<Tabs items={['v5 createClient', 'Legacy create']}>
<Tab value="v5 createClient">

The v5 programmatic API centers on `createClient` from `@open-wa/core`, re-exported through `@open-wa/wa-automate`. Use `createClient` for all new v5 custom code projects.

```ts
import { createClient } from '@open-wa/wa-automate';
import { PuppeteerDriver } from '@open-wa/driver-puppeteer';

async function start() {
  const client = await createClient({
    sessionId: 'my-session',
    driver: new PuppeteerDriver(),
    headless: true,
  });

  client.onMessage(async (message) => {
    if (message.body === 'Hi') {
      await client.sendText(message.from, '👋 Hello!');
    }
  });
}

start().catch(console.error);
```

During the initial run, authenticate the session by scanning the QR code in the terminal or using link-code pairing. Once the session is ready, incoming messages trigger the `onMessage` listener.

## Choose a browser driver explicitly

Install the driver package and client package that match your target runtime environment. The following example uses Puppeteer:

<PackageManagerTabs command="@open-wa/wa-automate @open-wa/client @open-wa/driver-puppeteer" />

Pass the driver instance to the `createClient` options object and instantiate the `Client` facade:

```ts
import { createClient } from '@open-wa/wa-automate';
import { PuppeteerDriver } from '@open-wa/driver-puppeteer';
import { Client } from '@open-wa/client';

async function start() {
  const openwa = await createClient({
    sessionId: 'my-session',
    driver: new PuppeteerDriver(),
    headless: true,
  });

  const client = new Client({
    client: openwa,
    transport: openwa.getTransport(),
  });
  await client.start();

  client.onMessage(async (message) => {
    if (message.body === 'Hi') {
      await client.sendText(message.from, '👋 Hello!');
    }
  });
}

start().catch(console.error);
```

## TypeScript configuration

Custom code projects work best with modern TypeScript compiler settings (`target: ES2022`, `moduleResolution: NodeNext` or `Bundler`). Ensure you `await` all asynchronous client methods.

## What runtime creation does

The `createClient` function:

1. Initializes the configured browser driver process.
2. Restores saved credentials from disk or initiates the authentication flow.
3. Injects the automation client into the WhatsApp Web session.
4. Returns an `OpenWAClient` instance managing browser lifecycle, events, and transport.

To execute messaging and domain operations, wrap the `OpenWAClient` with `new Client({ client: openwa, transport: openwa.getTransport() })` and call `await client.start()`.

## Build a custom launch configuration

```ts
import { createClient } from '@open-wa/wa-automate';
import { PuppeteerDriver } from '@open-wa/driver-puppeteer';

const openwa = await createClient({
  sessionId: 'sales',
  driver: new PuppeteerDriver(),
  headless: true,
  qrTimeout: 0,
  authTimeout: 60,
});
```

Specify explicit driver options whenever your deployment requires custom browser flags or non-default binary locations.

## Authentication lifecycle

During the initial launch, the runtime requires authentication. You can authenticate by scanning the QR code in the terminal or using an eight-digit pairing code.

After successful authentication, session credentials are saved to disk under the directory matching your configured `sessionId`. Subsequent process restarts reload this saved state automatically.

## Send and receive messages

The following example sends an initial status message to a specific chat ID and listens for incoming replies:

```ts
import { createClient } from '@open-wa/wa-automate';
import { PuppeteerDriver } from '@open-wa/driver-puppeteer';
import { Client } from '@open-wa/client';

async function start() {
  const openwa = await createClient({
    sessionId: 'sales',
    driver: new PuppeteerDriver(),
    headless: true,
  });

  const client = new Client({
    client: openwa,
    transport: openwa.getTransport(),
  });
  await client.start();

  const chatId = '15551234567@c.us';

  await client.sendText(chatId, 'Bot is online. Send Hi to test the reply flow.');

  client.onMessage(async (message) => {
    if (message.from === chatId && message.body === 'Hi') {
      await client.sendText(message.from, '👋 Hello from custom code.');
    }
  });
}

start().catch(console.error);
```

## Process cleanup and graceful shutdown

To release browser resources and cleanly exit when the host process terminates, register signal handlers that call `client.stop()`:

```ts
import { createClient } from '@open-wa/wa-automate';
import { PuppeteerDriver } from '@open-wa/driver-puppeteer';

async function start() {
  const client = await createClient({
    sessionId: 'sales',
    driver: new PuppeteerDriver(),
  });

  const shutdown = async () => {
    await client.stop();
    process.exit(0);
  };

  process.once('SIGINT', shutdown);
  process.once('SIGTERM', shutdown);
}

start().catch(console.error);
```

## Compare plugins and custom code

- **Plugins**: Use `@open-wa/plugin-sdk` to author reusable modular features that can be distributed as packages and loaded via configuration.
- **Custom code**: Use custom application code for application-specific business logic, database mutations, and internal message routing.

## Compare SocketClient and embedded runtime

- **SocketClient**: Connects over HTTP RPC and Server-Sent Events to an external Easy API daemon. Choose this when you want to isolate browser process overhead from your application service.
- **Embedded runtime**: Embeds the browser and client lifecycle directly in your Node.js process using `createClient`. Choose this when you need fine-grained control over driver initialization and browser configuration.

## Browser and runtime guidelines

- When using a system Chrome installation, pass `executablePath` explicitly in your configuration.
- On Linux servers, ensure required native libraries for Chromium are installed before launching headless browsers.
- Always handle errors asynchronously and register error listeners on the client instance.
