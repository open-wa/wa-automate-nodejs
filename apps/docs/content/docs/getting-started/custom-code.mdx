# Send your first WhatsApp message with the Node.js SDK

The SDK runs the WhatsApp session inside your Node.js process, so your code
calls methods and receives messages directly, with no HTTP server in between.
You need **Node.js 22.21.1 or newer** and a phone with WhatsApp to link.

## Reply to your first message

```bash
npm init @open-wa@latest my-bot -- --mode sdk
cd my-bot
npm start
```

Scan the QR code from **WhatsApp → Linked devices → Link a device**. When the
terminal prints `WhatsApp is ready. Send !ping from another account.`, send
`!ping` to the linked number from another phone. The bot answers `pong` in the
same chat, which confirms that receiving and replying both work. The
[generator options](/docs/getting-started/quickstart/generator-options) page
lists the language, browser and plugin choices.

## Send a message from a script

To add the SDK to an existing project instead, install the package and send
one message with [`sendText`](/docs/reference/client/messages#sendtext):

```bash
npm install @open-wa/wa-automate
```

```js title="send.mjs"
import { create } from '@open-wa/wa-automate';

const client = await create({ sessionId: 'my-bot' });

const messageId = await client.sendText('447123456789@c.us', 'Hello from open-wa');
console.log('Sent', messageId);

await client.stop();
```

```bash
node send.mjs
```

Replace `447123456789` with the recipient's full international number, without
`+` or spaces. The first run prints a QR code to scan. When the send works, the
terminal prints the message ID, such as `Sent true_447123456789@c.us_3EB0C7...`,
and the message appears in that chat on the phone. Later runs reuse the saved
login and skip the QR code.

Pick a recipient that has already chatted with the linked account. Starting a
chat with a new number needs a [license](/docs/licensing/pricing); without one,
`sendText` throws with code `LICENSE_REQUIRED`. The
[send guide](/docs/guides/send-message-api) covers chat IDs and the same send
over HTTP.

## The entry point

The generated `index.js` is the whole bot:

```js title="index.js"
import { create } from '@open-wa/wa-automate';
import config from './wa.config.js';

const client = await create(config);
console.log('WhatsApp is ready. Send !ping from another account.');

client.onMessage(async message => {
  if (!message.fromMe && message.body === '!ping') {
    await client.sendText(message.from, 'pong');
  }
});

for (const signal of ['SIGINT', 'SIGTERM']) {
  process.once(signal, () => {
    void client.stop(signal).catch(console.error);
  });
}
```

`create()` starts the browser, prints the QR code when the account isn't linked
yet, and resolves once the session is ready to send. Reply to `message.from`
exactly as it arrives, because it can be a phone-number ID (`@c.us`) or a
private ID (`@lid`); the [chat ID guide](/docs/guides/chatid-primer) explains
the formats. [`onMessage`](/docs/reference/client/events#message) fires for
messages other people send, and `client.stop()` closes the browser and keeps
the saved login.

The [`create()` reference](/docs/reference/create) lists its options, and the
[client reference](/docs/reference/client) lists the methods by job.

## Configuration

`wa.config.js` or `wa.config.ts` holds the session ID, browser choice and
plugin settings, and the entry point passes it to `create()`. `create()` uses
only the options you pass it. It doesn't read `WA_*` environment variables or
look for a config file on its own, so read secrets from `process.env` in your
config, as the generated file does:

```js title="wa.config.js"
export default {
  sessionId: 'my-bot',
  licenseKey: process.env.OPENWA_LICENSE_KEY || undefined,
};
```

The generated config loads `.env` when it exists. Plugins listed under
`plugins` run in SDK projects too, except Chatwoot, which needs Easy API.

## Saved login

After the first scan, the login is saved in an encrypted file named after the
session, such as `my-bot.data.json`, in the folder you run from. Set
`sessionDataPath` to keep it somewhere else. Start again with the same
`sessionId` and path and no QR code is needed. Treat the file like a password,
and keep one session ID per WhatsApp account.

## Errors

`sendText` throws a `SendTextError` when it fails. Its `outcome` is
`not_sent` when nothing was sent, or `unknown` when the message may have gone
out. Check the chat before you retry an unknown outcome; open-wa never retries a
send for you. Sending to a number with no existing chat throws with code
`LICENSE_REQUIRED` unless a [license](/docs/licensing/pricing) is applied.
