# Docker

The `openwa/wa-automate` image runs the [Easy API](/docs/getting-started/easy-api)
with Chrome and its system libraries already installed. You configure it with
`WA_*` environment variables and mount a folder for the saved login.

## Run the container

```bash
mkdir -p sessions
docker run --name openwa-sales --init \
  -p 127.0.0.1:8080:8080 \
  -v "$PWD/sessions:/sessions" \
  -e WA_SESSION_ID=sales \
  -e WA_SESSION_DATA_PATH=/sessions \
  -e WA_API_KEY="replace-with-a-long-random-key" \
  openwa/wa-automate:latest
```

What each setting does:

- `-p 127.0.0.1:8080:8080` publishes the API on your machine only. The image
  already sets `WA_HOST=0.0.0.0` so the server accepts connections from outside
  the container.
- `WA_SESSION_DATA_PATH=/sessions` saves the login file, `sales.data.json`, in
  the mounted folder so it survives the container being replaced; the
  [restart check](#restart-and-confirm-the-login-survived) confirms it.
- `WA_API_KEY` protects every method route. Use at least 8 characters.
- `--init` reaps the browser's child processes when they exit.

Scan the QR code printed in the container log (`docker logs -f openwa-sales`),
then check readiness from the host:

```bash
curl http://127.0.0.1:8080/health
```

Wait for `connected: true` and `session.ready: true` before sending. `/health`
can contain the pairing QR code, which is why the port is bound to loopback.

`latest` moves with each release. For production, pin the image by digest
(`openwa/wa-automate@sha256:…`) so a restart doesn't change versions under you.

## Keep secrets in an env file

```dotenv title=".env"
WA_SESSION_ID=sales
WA_SESSION_DATA_PATH=/sessions
WA_API_KEY=replace-with-a-long-random-key
```

```bash
docker run --name openwa-sales --init \
  -p 127.0.0.1:8080:8080 \
  -v "$PWD/sessions:/sessions" \
  --env-file .env \
  openwa/wa-automate:latest
```

Keep `.env` out of version control, and use your platform's secret store in
production. Any [configuration option](/docs/guides/configuration-and-cli) can
be set the same way: `WA_` followed by the option name in upper snake case,
such as `WA_LICENSE_KEY` for `licenseKey`.

## Docker Compose

```yaml title="compose.yaml"
services:
  openwa:
    image: openwa/wa-automate:latest
    init: true
    restart: unless-stopped
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - ./sessions:/sessions
    environment:
      WA_SESSION_ID: sales
      WA_SESSION_DATA_PATH: /sessions
      WA_API_KEY: ${WA_API_KEY:?Set WA_API_KEY in .env}
    healthcheck:
      test: ["CMD-SHELL", "wget -q --spider http://localhost:8080/health || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 3
```

```bash
docker compose up
```

The health check only proves the HTTP server answers. It doesn't mean WhatsApp
is linked.

## Memory and browser flags

Plan for about 700 MB to 1 GB of RAM per session. On small hosts, add
`--shm-size=1gb` to give Chrome more shared memory.

<Callout type="warning" title="Don't pass --single-process or --no-zygote">
These old low-memory Chromium flags break the browser and cause
`Navigating frame was detached` errors. open-wa removes them from
`chromiumArgs` unless you set `allowDangerousBrowserArgs: true`, which isn't
supported.
</Callout>

If Chrome fails to start or exits, see [error handling](/docs/operations/error-handling).

## Restart and confirm the login survived

The saved login is the file `<sessionId>.data.json` in `WA_SESSION_DATA_PATH`, here `/sessions/sales.data.json` inside the container and `./sessions/sales.data.json` on the host. Run this check once after the first scan, before you rely on the container:

1. **Check the file exists on the host.**

   ```bash
   ls sessions/
   ```

   The listing includes `sales.data.json`. If it doesn't, the volume or `WA_SESSION_DATA_PATH` is wrong, and a restart will ask for a new QR code.

2. **Replace the container.** Removing it is a harder test than `docker restart`, because nothing inside the old container survives:

   ```bash
   docker rm -f openwa-sales
   ```

   Then run the same `docker run` command as before, with the same `WA_SESSION_ID`, `WA_SESSION_DATA_PATH` and volume.

3. **Confirm the session is ready without a scan.**

   ```bash
   curl -s http://127.0.0.1:8080/health
   ```

   Repeat until the response has `"connected": true` and `"session": { "ready": true, ... }`. `docker logs openwa-sales` shows no QR code this time.

If a QR code appears, check that `sales.data.json` is in `./sessions` and that `WA_SESSION_ID` and `WA_SESSION_DATA_PATH` match the first run. Back the file up like a password, because anyone who copies it can use the account.
