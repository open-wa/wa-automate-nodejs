# Easy API quickstart

Use this guide to start a local WhatsApp HTTP API before writing custom Node.js application code.

## Start the Easy API server

```bash
npx @open-wa/wa-automate@alpha --port 8080
```

This starts an Easy API server on port `8080` and outputs the local API endpoint and interactive documentation URLs.

These examples specify port `8080` for consistency. If you omit `--port`, the v5 CLI defaults to port `8002`.

## Expected terminal output

```text
Easy API listening on http://localhost:8080
Interactive docs: http://localhost:8080/api-docs/
```

Open the documentation URL after the session connects. If you specified a custom port, adjust the URL accordingly.

## Core features

When the runtime starts successfully, it provides:

- An authentication flow in the terminal (QR code or link code)
- A local HTTP API endpoint
- Generated interactive API documentation for testing methods

## Common CLI options

```bash
# Specify a custom port
npx @open-wa/wa-automate@alpha --port 8080

# Protect the API with an API key
npx @open-wa/wa-automate@alpha --port 8080 --api-key "YOUR_SECURE_KEY"

# Start a named session
npx @open-wa/wa-automate@alpha --session-id sales --port 8081
```

## API key authentication

Use `--api-key "YOUR_SECURE_KEY"` to protect your API endpoints. The CLI accepts the key value via `--api-key`, `--key`, or `-k`.

```bash
npx @open-wa/wa-automate@alpha --port 8080 --api-key "YOUR_SECURE_KEY"
```

When making HTTP requests to the API, pass the key in the `X-API-Key` request header:

```bash
curl http://localhost:8080/api-docs/ \
  -H "X-API-Key: YOUR_SECURE_KEY"
```

## Best practices for your first session

- Set a `sessionId` if you plan to manage more than one WhatsApp account.
- Configure an `apiKey` before exposing the service over a network.
- Treat Easy API as a runtime daemon and place your business logic in separate consumer processes.

## Session persistence

Easy API stores browser profile data on disk so that subsequent restarts reuse the existing authenticated session.

The profile directory name is derived from the `sessionId`. For `--session-id sales`, the local data directory is `./_IGNORE_sales`. When no session ID is specified, the runtime uses `./_IGNORE_session`.

To persist session data across restarts:

1. Always launch the process from the same working directory.
2. Specify the same `--session-id` flag on startup.
3. To back up session data, stop the process and copy the `_IGNORE_*` directory to secure backup storage.

## Authentication methods

- **QR code scan**: Scan the terminal QR code using WhatsApp on your mobile phone.
- **Link-code authentication**: Use [link-code login](/docs/getting-started/link-code) to authenticate with an eight-digit pairing code instead of scanning a QR code.

For a complete walkthrough, see the [Quickstart](/docs/getting-started/quickstart) guide.

## Deployment guidelines

- Use `--host` or `-h` to specify the local bind address.
- Use distinct `--session-id` values and unique ports when running multiple sessions on a single host.
- Configure a process manager or container restart policy for production reliability.

## Security considerations

<Callout type="warning">
Do not expose Easy API directly to the public internet without an authentication layer. Always enforce an API key, place the server behind a secure reverse proxy with HTTPS, and restrict access to the `/api-docs/` endpoint.
</Callout>

## Remote access and proxying

The current v5 CLI displays a warning if you provide `--tunnel`. For secure remote access to a local session, use the [Cloudflare session proxy](/docs/client-and-integrations/cf-proxy).

## Webhooks configuration

In version 5, configure `@open-wa/integration-webhook` in `wa.config.mjs` for reliable event delivery.

## Load plugins from configuration

Specify plugins in your `wa.config.mjs` configuration file:

```ts
export default {
  plugins: [
    '@open-wa/integration-webhook',
    './my-local-plugin',
  ],
  pluginConfig: {
    webhook: {
      url: 'https://example.com/webhook',
    },
  },
};
```

## Process management with PM2

To run Easy API with automatic restarts under PM2:

```bash
npx @open-wa/wa-automate@alpha --pm2 --session-id STICKER_BOT --port 8080
```
