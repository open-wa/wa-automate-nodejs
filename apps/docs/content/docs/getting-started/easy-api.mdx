# Easy API

Easy API runs the WhatsApp session in one Node.js process and lets any program
control it over HTTP. Use it when your application isn't written in Node.js,
runs on another machine, or when you want the Neo dashboard. You need
**Node.js 22.21.1 or newer**.

## Start the server

Generate a project and set an API key before the first start:

```bash
npm init @open-wa@latest my-api -- --mode easy-api
cd my-api
cp .env.example .env
```

Put a long random value in `.env` as `WA_API_KEY` (at least 8 characters), then
start it:

```bash
npm start
```

Scan the QR code from **WhatsApp → Linked devices → Link a device**. The server
listens on `127.0.0.1:8080` and prints the addresses of the dashboard and API
explorer:

- Neo dashboard: [http://127.0.0.1:8080/dashboard/](http://127.0.0.1:8080/dashboard/) (on your machine)
- API explorer: [http://127.0.0.1:8080/api-docs/](http://127.0.0.1:8080/api-docs/) (on your machine)

Without a generated project, `npx @open-wa/wa-automate --session-id my-api --api-key "<key>"`
starts the same server. See [configuration](/docs/guides/configuration-and-cli)
for every flag, the config file and the `WA_*` environment variables.

## Wait for readiness

The HTTP server answers before WhatsApp has finished linking. Check `/health`
and wait until `connected` and `session.ready` are both `true`:

```bash
curl http://127.0.0.1:8080/health
```

```json
{
  "status": "ok",
  "connected": true,
  "session": { "state": "READY", "status": "ready", "ready": true, "pending": [], "blockers": [] }
}
```

Until then, method calls return `503` with
`{ "error": "API not available until the session is truly ready", "status": 503 }`.
`/health` doesn't need the API key.

## Send a message

Every method has a `POST` route under `/api/<namespace>/<method>` that takes
the method's parameters as a JSON object. Send the key in the `X-API-Key`
header; the examples read it from a `WA_API_KEY` variable in your shell, so run
`export WA_API_KEY='<your key>'` first. Use a chat ID from a conversation the linked account already has;
starting a chat with a new number needs a [license](/docs/licensing/pricing).

```bash tab="cURL" tab-group="openwa-http-language" title="HTTP request"
curl --fail-with-body http://127.0.0.1:8080/api/messages/sendText \
  -H "X-API-Key: $WA_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"to": "447700900123@c.us", "content": "Hello from Easy API"}'
```

```js tab="JavaScript" title="Node.js fetch"
const response = await fetch('http://127.0.0.1:8080/api/messages/sendText', {
  method: 'POST',
  headers: {
    'X-API-Key': process.env.WA_API_KEY,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ to: '447700900123@c.us', content: 'Hello from Easy API' }),
});
if (!response.ok) throw new Error(await response.text());
const { data: messageId } = await response.json();
console.log(messageId);
```

```python tab="Python" title="Python · requests"
import os
import requests

response = requests.post(
    "http://127.0.0.1:8080/api/messages/sendText",
    headers={"X-API-Key": os.environ["WA_API_KEY"]},
    json={"to": "447700900123@c.us", "content": "Hello from Easy API"},
    timeout=30,
)
response.raise_for_status()
print(response.json()["data"])
```

A successful call returns `{ "success": true, "data": ... }`. For `sendText`,
`data` is the new message ID:

```json
{ "success": true, "data": "true_447700900123@c.us_3EB0C767D1D7E8A2F1C4" }
```

That ID means WhatsApp accepted the message, not that it was delivered. A
failure returns an HTTP error with `{ "error": "..." }`. If the error says the
outcome is unknown, check the chat before sending again, because the message
may already be there.

## Receive messages

Open the event stream before you need it. It's a Server-Sent Events stream
filtered by `topics`:

```bash
curl --no-buffer 'http://127.0.0.1:8080/api/events?topics=message.received,ack.changed' \
  -H "X-API-Key: $WA_API_KEY"
```

Each `data:` line is a JSON envelope with `id`, `event`, `payload`, `ts` and
`sessionId`. An incoming message is at `payload.message`. The stream doesn't
replay events you missed while disconnected.

For a server that should receive messages without holding a connection open,
use a webhook. [Receive messages](/docs/guides/receive-messages) compares the
stream, webhooks and `onMessage`, and
[Receive webhooks](/docs/guides/receive-webhooks) sets one up. A Node.js
program on another machine can use [SocketClient](/docs/guides/socket-client)
to call methods and listen as if it ran the SDK.

## Media and other methods

File paths in a request are read on the Easy API machine, so send a public URL
or a data URL when the file lives elsewhere. The [API explorer](http://127.0.0.1:8080/api-docs/)
(on your machine) and the [API reference](/docs/reference/client/client) list
each method's fields. Start with [media](/docs/guides/media),
[interactive messages](/docs/guides/interactive-messages) and
[calendar events](/docs/guides/whatsapp-events).

## Keep it private

`/health` is public and can include the pairing QR code, so keep the server on
`127.0.0.1` or a private network and don't expose `/health` through a public
proxy. Send `X-API-Key` on every other request and use HTTPS for anything that
leaves the machine. [Docker](/docs/getting-started/docker) runs the same server
in a container, and [Cloudflare session proxy](/docs/guides/cf-proxy) reaches
it without opening a port.

Before customers depend on it, work through
[go to production](/docs/operations/go-to-production).
