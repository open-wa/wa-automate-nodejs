# Quickstart

Follow these steps to start a local API server, connect a WhatsApp account, and send a test message.

## Prerequisites

- **Node.js**: `>= 22.21.1` (required; verify using `node --version`)
- **npm** or **pnpm**: Package manager for installing dependencies
- **WhatsApp account**: Active account on a phone with internet access

<Callout type="warning">
**Version 5 is in alpha.** Test in a disposable environment before deploying to production. For production systems, use version 4: `npx @open-wa/wa-automate@4.76.0`
</Callout>

<Steps>
<Step title="Start the Easy API">

Run the CLI to start a local WhatsApp API server:

```bash
npx @open-wa/wa-automate@alpha --port 8080
```

These examples specify port `8080` for consistency. If you omit `--port`, the v5 CLI defaults to port `8002`.

The terminal logs display:

- Browser process launch status
- A QR code in the terminal
- The local API server URL (`http://localhost:8080`)

</Step>
<Step title="Authenticate the session">

The runtime displays a QR code in your terminal. On your mobile phone:

1. Open WhatsApp.
2. Tap **Settings** (iOS) or the three-dot menu (Android).
3. Select **Linked Devices**.
4. Tap **Link a Device**.
5. Scan the QR code displayed in your terminal.

If you know the phone number in advance, you can use [link-code login](/docs/getting-started/link-code) to authenticate using an eight-digit code instead of scanning a QR code.

After authentication completes, the terminal logs indicate that the session is connected and the API is ready.

</Step>
<Step title="Verify the API endpoint">

Open your browser to:

```text
http://localhost:8080/api-docs/
```

This page provides interactive API documentation for your active session. You can inspect all available methods and test requests directly.

Additional metadata endpoints:

- `http://localhost:8080/meta/swagger.json`: OpenAPI 3.0 specification
- `http://localhost:8080/meta/postman.json`: Postman collection

</Step>
<Step title="Send your first message">

<Tabs items={['API documentation UI', 'curl']}>
<Tab value="API documentation UI">

1. Open `http://localhost:8080/api-docs/` in your browser.
2. Locate the `sendText` method.
3. In the `to` field, enter a chat ID (such as your own phone number in the format `1234567890@c.us`).
4. In the `text` field, enter a message body.
5. Click **Execute** to send the request.

</Tab>
<Tab value="curl">

```bash
curl -X POST http://localhost:8080/api/sendText \
  -H "Content-Type: application/json" \
  -d '{"to": "1234567890@c.us", "text": "Hello from open-wa!"}'
```

If you started the API with an API key (`--api-key "YOUR_SECURE_KEY"`), include the `X-API-Key` header:

```bash
curl -X POST http://localhost:8080/api/sendText \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_SECURE_KEY" \
  -d '{"to": "1234567890@c.us", "text": "Hello from open-wa!"}'
```

The recipient device receives the message.

Example successful response:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "success": true,
  "data": "true_1234567890@c.us_EXAMPLE"
}
```

Example authentication failure response:

```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{
  "error": "Unauthorized"
}
```

If the API is protected with an API key, requests without a valid `X-API-Key` header return a `401 Unauthorized` status code.

</Tab>
</Tabs>

</Step>
</Steps>

## Common CLI commands

```bash
# Protect the API with an API key
npx @open-wa/wa-automate@alpha --port 8080 --api-key "YOUR_SECURE_KEY"

# Start a named session
npx @open-wa/wa-automate@alpha --session-id sales --port 8081

# Note: In version 5, configure @open-wa/integration-webhook in wa.config.mjs
# for source-backed webhook delivery rather than using the --webhook CLI flag.
```
