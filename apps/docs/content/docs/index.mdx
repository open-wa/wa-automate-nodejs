# open-wa / wa-automate

`open-wa` gives you a few different ways to automate WhatsApp, and the docs are now organized around those real usage modes instead of the old autogenerated Docusaurus tree.

<Callout type="info" title="Use this page as the docs router">
  If you are new, pick a runtime path first. If you are already integrating,
  jump straight to the guides, data-model pages, or reference sections linked
  below.
</Callout>

## Start here

<Steps>
  <Step title="Start with Easy API if you want speed">
    Use **[Getting Started](/docs/getting-started/easy-api)** when you want a
    running API quickly and plan to layer webhooks, dashboards, or remote
    consumers on top.
  </Step>
  <Step title="Start with Custom Code if your app owns the runtime">
    Use **[Custom Code](/docs/getting-started/custom-code)** when you want the
    client surface in-process inside your own Node.js application.
  </Step>
  <Step title="Start with Socket Client if the runtime already lives elsewhere">
    Use **[Socket Client](/docs/client-and-integrations/socket-client)** if you
    are consuming a remote Easy API instance and do not want to embed the
    browser automation runtime directly.
  </Step>
  <Step title="Use Cloudflare Session Proxy for tighter remote access control">
    Use **[Cloudflare Session Proxy](/docs/client-and-integrations/cf-proxy)**
    when you need remote session access without directly exposing a public port.
  </Step>
</Steps>

## Migration notes

This Fumadocs site intentionally does **not** mirror the old legacy sidebar one-to-one. The legacy site had ordering collisions, flat how-to sprawl, and orphaned docs outside the main tree. Content has been regrouped so task-oriented material is easier to find and maintain.

<Callout type="tip" title="Legacy user shortcut">
  If you previously navigated by the old Docusaurus categories, the quickest new
  anchors are usually **Configuration and CLI**, **Session events**,
  **Socket Client**, **Data models**, and **Pricing and licensing**.
</Callout>
