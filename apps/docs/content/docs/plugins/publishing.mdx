# Publishing a plugin

Once you have built a custom open-wa plugin, you can publish it to the public npm registry (or a private package registry) to share it across projects.

## Distribution model

<Callout type="info">
Plugins are standard npm packages. Users install them using their preferred package manager and register them in their `wa.config.mjs` configuration.
</Callout>

The publishing workflow comprises four steps:

1. Build and bundle your plugin module with TypeScript.
2. Publish the package to npm.
3. Consumers install the package with `npm install` or `pnpm add`.
4. Consumers register the package name in their `plugins` array.

## Package structure

### Manifest configuration (package.json)

```json
{
  "name": "@myorg/my-plugin",
  "version": "1.0.0",
  "description": "Custom open-wa plugin for CRM synchronization",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "types": "./dist/index.d.ts"
    }
  },
  "files": [
    "dist"
  ],
  "peerDependencies": {
    "@open-wa/plugin-sdk": ">=5.0.0"
  },
  "scripts": {
    "build": "tsc",
    "prepublishOnly": "npm run build"
  }
}
```

### Key manifest properties

- `name`: Use a scoped package name (`@myorg/my-plugin`) to prevent namespace collisions.
- `main` and `exports`: Point to compiled JavaScript bundles in `dist/`.
- `types`: Declare the path to generated TypeScript declaration files (`.d.ts`).
- `files`: Include only build output in the published archive.
- `peerDependencies`: Specify the supported `@open-wa/plugin-sdk` version range.

### TypeScript build configuration

Configure `tsconfig.json` to emit declaration files:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "declaration": true,
    "outDir": "dist",
    "rootDir": "src",
    "strict": true,
    "esModuleInterop": true
  },
  "include": ["src"]
}
```

## Versioning

### Semantic versioning

Follow Semantic Versioning (`MAJOR.MINOR.PATCH`):

- **MAJOR**: Breaking changes (such as modified hook payloads or updated configuration schema keys)
- **MINOR**: Backward-compatible new features (such as new tools, routes, or hooks)
- **PATCH**: Backward-compatible bug fixes

### Compatibility with open-wa releases

Declare compatibility ranges in `package.json`:

```json
{
  "peerDependencies": {
    "@open-wa/plugin-sdk": ">=5.0.0 <6.0.0"
  },
  "engines": {
    "node": ">=22.21.1"
  }
}
```

### Breaking change management

When publishing a major version:

- Document migration steps in the package `README.md`.
- Detail breaking changes in GitHub release notes.
- Emit runtime deprecation warnings prior to removing functionality.

## Installation and usage instructions

### Package installation

Provide installation commands in your plugin documentation:

```bash
npm install @myorg/my-plugin
```

### Configuration example

Document the configuration structure required in `wa.config.mjs`:

```js
export default {
  plugins: [
    '@myorg/my-plugin',
  ],
  pluginConfig: {
    'my-plugin': {
      apiUrl: 'https://api.example.com',
      apiKey: process.env.MY_PLUGIN_API_KEY,
    },
  },
};
```

## Documentation guidelines

### README template

Include a clear usage template in your repository `README.md`:

````markdown
# @myorg/my-plugin

Brief description of the plugin's functionality.

## Installation

```bash
npm install @myorg/my-plugin
```

## Configuration

Add the plugin to `wa.config.mjs`:

```js
export default {
  plugins: ['@myorg/my-plugin'],
  pluginConfig: {
    'my-plugin': {
      apiKey: process.env.MY_PLUGIN_API_KEY,
      timeoutMs: 5000,
    },
  },
};
```

## Configuration reference

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `apiKey` | `string` | Yes | - | API key for upstream authentication |
| `timeoutMs` | `number` | No | `5000` | Request timeout in milliseconds |
````

## Testing plugins locally

### Test with a local file path

Before publishing, load the local build directory directly:

```js
export default {
  plugins: [
    './path/to/my-plugin/dist/index.js',
  ],
  pluginConfig: {
    'my-plugin': {
      apiKey: 'test-key',
    },
  },
};
```

### Test with isolated sessions

Run tests using an isolated temporary session:

```bash
npx @open-wa/wa-automate@alpha --session-id plugin-test --port 8080
```

### Multi-session verification

If your plugin stores state or manages caching, verify that multiple sessions executing concurrently do not corrupt shared state.
