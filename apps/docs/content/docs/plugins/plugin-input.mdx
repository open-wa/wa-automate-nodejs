# PluginInput reference

When open-wa invokes a plugin's `init()` method, it passes a `PluginInput` object containing event emitters, scoped loggers, validated configuration, and client proxies.

## Interface definition

```ts
interface PluginInput<TConfig = unknown> {
  events: PluginEventEmitter;
  logger: PluginLogger;
  config: TConfig;
  sessionId: string;
  client: PluginClient;
}
```

## The events gateway

The `events` property provides a security-filtered event bus.

### Allowed operations

Subscribe to public messaging and lifecycle events using `on()`, `once()`, and `off()`:

```ts
events.on('message.received', (payload) => {
  logger.info('Received incoming message payload');
});
```

### Restricted operations

- **Event emission**: Plugins cannot dispatch events onto the internal event bus.
- **System events**: Internal events prefixed with `launch.*`, `browser.*`, or `transport.*` are filtered out.
- **Sensitive events**: Licensing payloads (`license.*`) and authentication session data are inaccessible.

## The logger utility

The `logger` provides structured logging automatically prefixed with your plugin's `meta.name`.

### Logging methods

```ts
logger.info('Plugin initialized', { version: '1.0.0' });
logger.warn('Configuration property missing; applying default');
logger.error('Failed to connect to upstream service', { error: 'ECONNREFUSED' });
logger.debug('Processing message payload', { messageId: '3EB0A1B2' });
```

Available log levels:

- `logger.info(message, meta?)`: Informational messages
- `logger.warn(message, meta?)`: Operational warnings
- `logger.error(message, meta?)`: Error events and stack traces
- `logger.debug(message, meta?)`: Verbose debugging output (enabled via debug log levels)

### Automatic prefixing

All log messages include the plugin identifier prefix:

```text
[greeting-bot] Plugin initialized { version: '1.0.0' }
```

### Log persistence

Plugin log messages stream into the host process logging pipeline (writing to standard output and standard error by default).

## Validated configuration (config)

The `config` property contains plugin options parsed from `wa.config.mjs`, validated against your plugin's `configSchema`.

### Configuration access pattern

Specify options under `pluginConfig.<plugin-name>` in `wa.config.mjs`:

```js
// wa.config.mjs
export default {
  pluginConfig: {
    'my-plugin': {
      apiUrl: 'https://api.example.com',
      apiKey: process.env.MY_PLUGIN_API_KEY,
    },
  },
};
```

Access the validated values inside your plugin:

```ts
// my-plugin.ts
export default createPlugin({
  meta: { name: 'my-plugin' },
  configSchema,

  init: async ({ config }) => {
    // Typed as { apiUrl: string; apiKey: string }
    console.log('Connecting to API:', config.apiUrl);
  },
});
```

### Automatic type inference

When you define a `configSchema` using Zod, TypeScript infers the exact shape of `config`:

```ts
const configSchema = z.object({
  apiUrl: z.string().url(),
  apiKey: z.string().min(1),
  retries: z.number().int().positive().default(3),
});

// config is typed as { apiUrl: string; apiKey: string; retries: number }
init: async ({ config }) => {
  // TypeScript enforces properties on config
};
```

## Session identifier (sessionId)

`sessionId` contains the unique string identifier for the active WhatsApp session:

```ts
init: async ({ sessionId, logger }) => {
  logger.info('Plugin loaded for session', { sessionId });
};
```

Use `sessionId` to partition data storage, segment audit records, or scope multi-tenant integrations.

## WhatsApp client proxy (client)

The `client` object is a transport-agnostic proxy exposing WhatsApp automation methods:

```ts
init: async ({ client }) => {
  await client.sendText('447700900000@c.us', 'Service initialized');
  const hostNumber = await client.getHostNumber();
};
```

For the complete method list, see the [PluginClient reference](/docs/plugins/plugin-client).
