# Dashboard Pages

Continue with `greeting-bot.mjs` and `wa.config.mjs` from [Plugin getting started](/docs/plugins/getting-started). The starter returns its message hook, route, and page declaration from async `init()`.

## Declare a page from `init()`

In `greeting-bot.mjs`, add `pages` to the object already returned by `init()`, alongside the message hook and `routes`:

```js
pages: [{
  path: '/',
  title: 'Greeting bot',
  icon: '👋',
  description: 'The plugin is loaded and its health route is available.',
}],
```

Open the [local dashboard](http://localhost:8080/dashboard/) and select **Greeting bot**. The supported status view is at `/dashboard/plugins/greeting-bot`; another path can change the sidebar link but does not create a matching screen or custom plugin UI.

### Page properties

- **`path`**: The path segment used in dashboard navigation. Use `/` for the standard status view; other values do not enable custom dashboard rendering.
- **`title`**: The label shown in the sidebar.
- **`icon`**: An emoji or icon name shown beside the label.
- **`order`**: Optional ordering metadata; the current dashboard does not use it to sort plugin pages.
- **`description`**: Optional page metadata; the current dashboard does not display it. Use the plugin's `meta.description` for the status view summary.

## Add plugin-owned data

The declaration adds status information and a sidebar link; it does not render a custom plugin interface. In the starter, open [the health route](http://localhost:8080/plugins/greeting-bot/health) for the plugin's JSON response. Use the [HTTP routes guide](/docs/plugins/hono-routes) to add endpoints for other plugin-owned data.
