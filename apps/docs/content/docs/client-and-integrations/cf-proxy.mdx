# Cloudflare session proxy

The **Cloudflare session proxy** (`@open-wa/cf-proxy`) allows you to access WhatsApp sessions remotely without opening inbound network ports or configuring public firewall rules.

Local open-wa instances establish an outbound WebSocket connection to a Cloudflare Durable Object, which relays incoming HTTP and Server-Sent Events traffic from remote consumers.

## How the proxy works

```text
Consumer (HTTP / SocketClient)
       │
       ▼
 Cloudflare Worker (Authentication gate)
       │
       ▼
 Durable Object (Per-session state)
       │
       ▼
 Local CLI TunnelClient -> Local WhatsApp session
```

1. You deploy the Worker to your Cloudflare account.
2. The local open-wa CLI establishes an outbound WebSocket tunnel to the Worker.
3. Remote consumers dispatch requests to the Worker URL. The Durable Object routes traffic across the active tunnel.
4. When idle, WebSockets hibernate with zero compute charges.

## Installation and setup

### Install the package

Install the proxy package in your project workspace:

<PackageManagerTabs command="install @open-wa/cf-proxy" />

### Prerequisites

Deploying the proxy requires the Cloudflare Wrangler CLI:

```bash
npm install -g wrangler
wrangler login
wrangler whoami
```

Verify that Workers and Durable Objects are enabled on your Cloudflare account.

### Step 1: Deploy the Cloudflare Worker

```bash
cd packages/cf-proxy
wrangler secret put UPSTREAM_TOKEN
wrangler secret put CONSUMER_TOKEN
wrangler deploy
```

- `UPSTREAM_TOKEN`: Secret token used by the local open-wa CLI when opening the reverse tunnel.
- `CONSUMER_TOKEN`: Secret token required by remote clients connecting through the Worker.

### Durable Object bindings

The Worker assigns each active tunnel to a dedicated Durable Object keyed by session ID. Verify that `wrangler.toml` defines the `SESSION_TUNNEL` binding:

```toml
name = "open-wa-proxy"
main = "src/index.ts"
compatibility_date = "2026-05-19"

[[durable_objects.bindings]]
name = "SESSION_TUNNEL"
class_name = "SessionTunnel"

[[migrations]]
tag = "v1"
new_classes = ["SessionTunnel"]
```

### Step 2: Start a session with proxy tunneling

Launch the local CLI session with proxy parameters:

```bash
wa --session-id sales \
   --proxy-host https://open-wa-proxy.YOUR_ACCOUNT.workers.dev \
   --proxy-token UPSTREAM_TOKEN
```

Or configure the options in `wa.config.mjs`:

```js
export default {
  sessionId: 'sales',
  proxyHost: 'https://open-wa-proxy.YOUR_ACCOUNT.workers.dev',
  proxyToken: process.env.UPSTREAM_TOKEN,
};
```

### Local session lifecycle

The proxy Worker does not run WhatsApp Web directly. Your local machine manages the Chromium browser instance, session storage, and Easy API server. The Worker acts strictly as an authenticated transport relay.

## Connect to the proxied session

Connect remote applications using `SocketClient`:

```ts
import { SocketClient } from '@open-wa/socket-client';

const client = await SocketClient.connect(
  'cf-proxy://open-wa-proxy.YOUR_ACCOUNT.workers.dev?sessionId=sales&token=CONSUMER_TOKEN'
);
```

## HTTP request examples

Interact directly with the proxied Easy API over HTTP:

### Read session details

```bash
curl "https://open-wa-proxy.YOUR_ACCOUNT.workers.dev/sessions/sales/api/getHostNumber?token=CONSUMER_TOKEN"
```

### Dispatch a text message

```bash
curl -X POST "https://open-wa-proxy.YOUR_ACCOUNT.workers.dev/sessions/sales/api/sendText" \
  -H "Authorization: Bearer CONSUMER_TOKEN" \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"args":["447700900000@c.us","Hello from Cloudflare proxy"]}'
```

## Authentication tokens

| Token | Description |
| --- | --- |
| `UPSTREAM_TOKEN` | Authenticates the local CLI establishing the reverse tunnel |
| `CONSUMER_TOKEN` | Authenticates external clients accessing the proxied session |

## Rotate authentication tokens

To rotate the consumer token:

```bash
cd packages/cf-proxy
wrangler secret put CONSUMER_TOKEN
wrangler deploy
```

Update your remote client connection strings to use the updated token.

To rotate the upstream tunnel token:

```bash
cd packages/cf-proxy
wrangler secret put UPSTREAM_TOKEN
wrangler deploy
```

Restart your local CLI daemon with the new `--proxy-token` value.

## Configure custom domains

To route proxy traffic through a custom domain on your Cloudflare zone, add a route entry to `wrangler.toml`:

```toml
routes = [
  { pattern = "wa-proxy.example.com/*", custom_domain = true }
]
```

Deploy the updated configuration:

```bash
wrangler deploy
```

Connect your local session and clients using the custom domain:

```bash
wa --session-id sales \
   --proxy-host https://wa-proxy.example.com \
   --proxy-token UPSTREAM_TOKEN
```

```ts
const client = await SocketClient.connect(
  'cf-proxy://wa-proxy.example.com?sessionId=sales&token=CONSUMER_TOKEN'
);
```

## Use the proxy in plugins

Plugins running on external infrastructure can dispatch commands through the proxy:

```ts
const proxyHost = process.env.OPENWA_PROXY_HOST;
const sessionId = process.env.OPENWA_SESSION_ID;
const consumerToken = process.env.OPENWA_CONSUMER_TOKEN;

await fetch(`${proxyHost}/sessions/${sessionId}/api/sendText`, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${consumerToken}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    args: ['447700900000@c.us', 'Dispatched from external plugin'],
  }),
});
```

## Troubleshooting

### Error: Unauthorized upstream

The `--proxy-token` passed to the local CLI does not match the `UPSTREAM_TOKEN` secret deployed on Cloudflare. Update the secret or update the CLI argument.

### Error: Unauthorized consumer

The remote client omitted `CONSUMER_TOKEN` or supplied an invalid value. Pass the token via the `Authorization: Bearer <TOKEN>` header or the `token` URL query parameter.

### Error: Session offline

The Cloudflare Worker received the request, but no local CLI tunnel is connected for the specified `sessionId`. Verify that your local daemon is running and has established an active tunnel connection.

### WebSocket connection failures

Confirm that `--proxy-host` specifies an `https://` scheme. The CLI automatically negotiates the upgrade to `wss://`.

### HTTP 504 gateway timeout

The Durable Object forwarded the request across the tunnel, but the local Easy API server did not return a response before the timeout threshold. Verify that the local session is responsive.

### SocketClient connects but commands fail

Ensure you provide both the `CONSUMER_TOKEN` for the Cloudflare proxy and the `X-API-Key` required by your local Easy API server configuration.
