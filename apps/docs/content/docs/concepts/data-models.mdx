# Data models

This guide details the core data structures used across the open-wa client, event listeners, webhooks, and generated API references.

<Callout type="info" title="Companion reference">
Read the task-oriented guides when building application logic. Use this reference when you need the exact object shape for messages, chats, contacts, and group metadata.
</Callout>

## Chat ID formats

Every message operation requires a target chat ID.

### Direct chats

For direct one-to-one chats, take the phone number in international format, remove all punctuation and leading plus signs, and append the `@c.us` domain suffix:

```text
+44 7700 900000
447700900000
447700900000@c.us
```

### Group chats

Groups use the `@g.us` suffix. WhatsApp assigns group IDs upon creation; you cannot construct them from phone numbers. Retrieve group IDs from incoming messages, group listings, or invite metadata:

```text
120363025814912345@g.us
```

### Linked device identifiers (LIDs)

LIDs represent internal linked device identities. They may appear in sender or participant fields. Treat LIDs as opaque identifiers for equality checks and routing rather than formatting them as standard phone numbers.

## Message direction

Use the boolean property `fromMe` to determine message direction:

- `fromMe: false`: The message is incoming from a contact or group.
- `fromMe: true`: The message was sent by the current session.

The `self` property provides the direction as a string (`in` or `out`). Use `fromMe` for boolean branch logic, and use `self` when recording audit logs or structured database rows.

In direct conversations, `from` identifies the sender and `to` identifies the recipient. In group conversations, `from` contains the group chat ID, while `author` (or `senderId`) indicates the participant who wrote the message.

## Message object

The `Message` object represents a single WhatsApp message event delivered to listeners and webhooks.

### Media properties

Media messages arrive as standard `Message` objects with `isMedia: true`. The `type` property specifies the media format (`image`, `video`, `audio`, `ptt`, `document`, or `sticker`).

Key media properties:

| Property | Description |
| --- | --- |
| `type` | WhatsApp message type (such as `image`, `video`, or `document`) |
| `mimetype` | MIME type of the media file (such as `image/jpeg` or `application/pdf`) |
| `caption` | Optional text caption included with the media |
| `mediaData` | Metadata required by the runtime to download and decrypt binary content |
| `clientUrl` | Ephemeral download URL provided in certain webhook payloads |

To retrieve decrypted binary content, pass the message object to `decryptMedia`:

```ts
import { decryptMedia } from '@open-wa/wa-automate';

client.onMessage(async (message) => {
  if (!message.isMedia && !message.mimetype) return;

  const mediaBuffer = await decryptMedia(message);
  // Process decrypted binary data
});
```

### Nullability patterns

IDs and timestamps are always present on valid message objects. Content fields vary depending on the message type:

| Property | Nullability condition |
| --- | --- |
| `body` | Null or empty for system messages, notifications, or media messages without captions |
| `caption` | Present only when text accompanied the media attachment |
| `quotedMsg` or `quotedMsgObj` | Present only when replying to a prior message currently cached in session memory |
| `author` or `senderId` | Present in group messages; omitted in direct one-to-one chats |
| `notifyName` | Present when the sender configured a public WhatsApp display name |
| `mimetype` or `mediaData` | Present only for decryptable media messages |

## Contact object

`Contact` objects describe individual WhatsApp users. Use the unique `id` field as the canonical key for lookups and message routing.

Common properties include `id`, `name`, `shortName`, `pushname`, `formattedName`, `isBusiness`, `isMyContact`, and `verifiedName`.

## Chat object

`Chat` objects represent conversation channels. For one-to-one chats, `isGroup` is `false`. For group chats, `isGroup` is `true` and `id` uses the `@g.us` suffix.

Common properties include `id`, `name`, `formattedTitle`, `isGroup`, `contact`, `groupMetadata`, `unreadCount`, and `presence`.

## Group metadata object

`GroupMetadata` contains configuration and membership details for a group conversation.

Key properties include `id`, `subject`, `owner`, `desc`, `restrict`, `announce`, and `participants`. Each participant entry defines `id`, `isAdmin`, and `isSuperAdmin`.
